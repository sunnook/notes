### 一、 多进程架构：从“单细胞”到“多细胞生物”

早期的浏览器是单进程的，一个标签页崩溃，整个浏览器就挂了。现代浏览器采用**多进程架构**，这是稳定性和安全性的基石。

```
┌─────────────────────────────────────────────────────────┐
│                    浏览器主进程 (Browser Process)         │
│  • UI 界面 (地址栏、书签、前进后退)                      │
│  • 进程管理 (创建/销毁其他进程)                          │
│  • 持久化存储 (Cookie, LocalStorage 的读写)               │
│  • 网络请求分发                                         │
└───────┬───────────────┬───────────────┬─────────────────┘
        │               │               │
        ▼               ▼               ▼
┌───────────────┐ ┌───────────┐ ┌───────────────┐
│  渲染进程 (N个) │ │ GPU 进程  │ │  网络进程 (1个) │
│  (每个站点一个) │ │           │ │               │
│               │ │ • 硬件加速 │ │ • HTTP/3 协议栈│
│ • 沙箱环境    │ │ • 合成图层 │ │ • DNS 解析     │
│ • 解析/渲染   │ │ • WebGL    │ │ • 缓存管理     │
│ • 执行 JS     │ │ • 视频解码 │ │ • 所有网络I/O  │
└───────┬───────┘ └───────────┘ └───────────────┘
        │
        ▼
┌───────────────────────────────────────┐
│          插件/扩展进程 (N个)            │
│  (每个扩展/插件一个，权限隔离)         │
└───────────────────────────────────────┘
```

**关键设计哲学：**

1. **沙箱隔离**：**渲染进程是绝对的“囚徒”**。它没有权限直接访问你的文件系统、网络或显示器。它想做任何事，都必须通过 **IPC（进程间通信）** 向浏览器主进程“打报告”。这就是为什么一个恶意网页很难突破浏览器去攻击你的系统。
2. **站点隔离**：即使是同一个域名的不同标签页，现在也倾向于放在不同的渲染进程里，彻底杜绝了 Spectre/Meltdown 这类 CPU 侧信道攻击的风险。
3. **职责分离**：网络、GPU 等高风险或高计算量的任务，由专门的独立进程处理，即使渲染进程崩溃，也不影响它们。

### 二、 渲染进程内部：一个“微型工厂”

这是最核心、最有趣的部分。一个渲染进程接收 HTML/CSS/JS，输出像素。它的内部是一条精密的流水线。

```
                     ┌───────────────────────────────┐
                     │         JavaScript 引擎        │
                     │           (V8 / JSC)           │
                     │  • 解析 JS → AST → 字节码      │
                     │  • 热点代码 → JIT 编译 → 机器码 │
                     │  • 垃圾回收 (GC)               │
                     │  • 与 Web API 的绑定层          │
                     └───────────────┬───────────────┘
                                     │
                                     ▼
┌──────────────────────────────────────────────────────────────────┐
│                          渲染引擎 (Blink / WebKit)                │
│                                                                  │
│  ① HTML 解析器 ──► ② CSS 解析器 ──► ③ DOM/CSSOM 树 ──► ④ 渲染树 │
│                                                                  │
│  ⑤ 布局 (Layout)      ⑥ 绘制 (Paint)       ⑦ 合成 (Composite)   │
│  ┌──────────────┐   ┌──────────────┐   ┌──────────────────────┐  │
│  │ 计算每个元素  │   │ 生成绘制指令  │   │ 将图层分块、光栅化    │  │
│  │ 的精确位置和  │ → │ 列表 (Paint   │ → │ 并交给 GPU 线程合成   │  │
│  │ 大小 (盒模型) │   │  Ops) 记录先  │   │ 最终屏幕画面          │  │
│  │              │   │ 画什么后画什么│   │                      │  │
│  └──────────────┘   └──────────────┘   └──────────────────────┘  │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

**流水线细节：**

1. **解析与构建**：HTML 解析器非常宽容，会边下载边解析，遇到 `<script>` 标签会暂停等待 JS 执行（因为 JS 可能修改 DOM）。CSS 解析器则构建 CSSOM 树，它不能边下载边解析，必须等全部规则下载完，因为它会层叠覆盖。
2. **布局 - 重排**：根据 DOM 树和 CSSOM 树，结合视口大小，计算出每个可见元素在屏幕上的精确几何位置和大小。任何一个元素的几何属性变化（如宽高、位置），都会触发整个流水线从这一步开始重来，这就是**重排**，代价极高。
3. **绘制 - 重绘**：根据布局阶段算出的几何信息，生成一系列绘制指令，如“先在 (0,0) 画一个红色矩形，再在 (10,10) 写黑色文字”。如果只是颜色、阴影等非几何属性变化，会跳过布局，直接触发这一步，这就是**重绘**。
4. **合成 - 最重要**：这是现代浏览器性能的关键。浏览器会将页面拆分成多个**图层**（比如固定定位的元素、Canvas、视频会单独成层）。每个图层在独立的线程中被光栅化（变成位图）。最后，**合成器线程**像拼图一样，把这些位图在 GPU 里合成最终画面。**`transform` 和 `opacity` 动画之所以流畅，就是因为它们只影响这最后一步，完全不需要触发重排或重绘。**

### 三、 网络栈：浏览器里的“协议栈”

网络进程内部实现了一个完整的现代网络协议栈。

```
┌────────────────────────────────────────────┐
│              应用层 (Web API)               │
│  fetch(), XMLHttpRequest, WebSocket,       │
│  WebRTC, Server-Sent Events                │
├────────────────────────────────────────────┤
│           会话/表示层 (安全与状态)           │
│  TLS 1.3 (BoringSSL), HTTP/3, Cookies,     │
│  Cache (HTTP Cache, Service Worker)        │
├────────────────────────────────────────────┤
│           传输层 (连接管理)                  │
│  QUIC, TCP, UDP, Socket Pool,             │
│  Connection Reuse                          │
├────────────────────────────────────────────┤
│           网络层 (优化与策略)                │
│  DNS (预解析), HTTP/2 多路复用,            │
│  Prioritization, Preconnect, Prefetch      │
└────────────────────────────────────────────┘
```

它不仅仅是调用操作系统的 Socket。它自己实现了：

- **HTTP/3 和 QUIC**：基于 UDP 的新一代协议，内置 TLS 1.3，实现 0-RTT 快速握手和多路复用，无队头阻塞。
- **连接池与调度**：管理对同一域名的并发连接数，决定请求的优先级（CSS 和可见图片优先于异步 JS）。
- **预测与优化**：在你还没点击链接时，浏览器就可能提前解析 DNS、建立 TCP/TLS 连接，甚至预渲染整个页面。

### 四、 安全沙箱：不可逾越的“结界”

这是整个架构的基石，贯穿所有进程。

- **渲染进程**：运行在最小权限的沙箱里。它不能打开文件，不能直接发网络请求，不能访问屏幕。它的一切操作都需要通过 IPC 向主进程请求，主进程会进行权限检查。
- **GPU 进程**：同样被沙箱化，只暴露有限的 OpenGL/Vulkan/Metal 接口给渲染进程，防止网页利用 GPU 驱动漏洞。
- **站点隔离**：确保不同站点的数据（HTML、JS、Cookie）在物理内存级别被隔离，一个恶意站点无法通过 Spectre 攻击窃取到你在另一个标签页里输入的银行密码。
