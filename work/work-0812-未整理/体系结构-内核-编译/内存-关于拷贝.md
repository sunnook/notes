```c
// 自定义深拷贝函数，复制整个结构体及其指向的数据
void AudFrameBuf_DeepCopy(AUD_FRAME_BUF_ST *dst, const AUD_FRAME_BUF_ST *src) {
    if (dst == NULL || src == NULL) {
        return; // 错误处理
    }
    
    // 复制基本字段（浅拷贝部分）
    *dst = *src; // 或使用 memcpy(dst, src, sizeof(AUD_FRAME_BUF_ST)); 但不如 = 安全
    
    // 深拷贝 pVirAddr 指向的数据
    if (src->pVirAddr != NULL) {
        // 分配新内存并复制数据
        dst->pVirAddr = (INT8*)malloc(src->uTotalLen); // 假设 uTotalLen 是缓冲区大小
        if (dst->pVirAddr != NULL) {
            memcpy(dst->pVirAddr, src->pVirAddr, src->uTotalLen);
        } else {
            // 处理分配失败
        }
    } else {
        dst->pVirAddr = NULL;
    }
}

// 使用示例：
AudFrameBuf_DeepCopy(pstAudResFrame, &pstAoDevInfo->stAudFrame);
```

#### 2. 如果资源是只读的，考虑使用引用计数（Reference Counting）：
- 为结构体添加引用计数字段（如 `refCount`），拷贝时只复制指针并增加计数，释放时减少计数，当计数为0时真正释放内存。这需要额外的管理逻辑，但能避免复制大数据。

### 四、总结
- **问题**：浅拷贝导致多个结构体实例共享同一块堆内存，引发悬空指针、双重释放或内存泄漏。
- **内存类型**：`pVirAddr` 指向的是堆上分配的音频数据缓冲区。
- **修复关键**：避免使用 `memcpy` 或直接赋值（`=`）来拷贝含指针的结构体。始终使用深拷贝来复制资源所有权。
