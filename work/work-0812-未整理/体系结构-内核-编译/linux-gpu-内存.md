- ✅ **系统DDR内存**
- ✅ 通过DMA-BUF框架分配，**物理上可能非连续**
- ✅ 硬件DMA引擎通过IOMMU访问

**特点**：
- 物理位置：系统DDR（可能分散）
- 分配方式：ION/DMA-BUF分配器
- 大小：较大（视频帧缓存：如4K帧 = 3840×2160×1.5 = 12MB）
- 硬件访问：DMA引擎通过IOMMU做地址转换

### 1. 算法连续内存 (MMZ)


- **用途**：算法模块需要连续物理地址访问

### 2. GPU渲染内存 (RENDER)
```c
stride = ALIGN_UP(pInParam->uWidth, 128);  // 强制128对齐
```
- **特点**：GPU可直接渲染的纹理内存
- **用途**：显示渲染、GPU纹理操作
- **对齐**：128字节对齐（**最严格**）
- **原因**：GPU硬件要求跨距128对齐以保证渲染性能

### 3. 普通视频帧DMA内存

```c
pInParam->uWidth = ALIGN_UP(pInParam->uWidth, 16);   // 宽16对齐

stride = pInParam->uWidth;
```
- **特点**：通用DMA内存
- **用途**：视频帧缓存、DMA传输
- **对齐**：宽高都16对齐（**会修改原始参数**）
- **原因**：芯片平台特性要求强制16位对齐

1. **对齐要求递增**：MMZ(4) < DMA(16) < RENDER(128)

---


</think>## MMZ 和 CMA 的含义

### **MMZ (Media Memory Zone)**
- **海思/海康专有术语**，指为多媒体处理预留的**连续物理内存区域**
- 在系统启动时，从DDR中划出一块**专属区域**，禁止Linux内核使用
- 类似"圈地运动"：这块内存不参与内核的伙伴系统管理

### **CMA (Contiguous Memory Allocator)**
- **Linux内核标准机制**，用于分配**大块连续物理内存**
- 与MMZ的区别：CMA区域在**不使用时**可以被内核正常使用（可移动页面）
- 需要连续内存时，内核会迁移CMA区域中的可移动页面，腾出连续空间
