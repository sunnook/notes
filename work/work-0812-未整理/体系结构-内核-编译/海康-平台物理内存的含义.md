嵌入式平台内存和流媒体内存





## 平台物理内存的含义

结合之前的讨论，**平台物理内存**在这里有特定含义：

### 不是物理上独立的 DDR 芯片

```
常见误解：
┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐
│ DDR 0   │  │ DDR 1   │  │ DDR 2   │  │ DDR 3   │
│ 芯片1   │  │ 芯片2   │  │ 芯片3   │  │ 芯片4   │
└─────────┘  └─────────┘  └─────────┘  └─────────┘
     ↑ 实际很少这样设计

实际情况：
┌─────────────────────────────────────────────────┐
│              同一块 DDR 物理内存 (4GB)             │
│                                                 │
│  ┌───────────────┐  ← 逻辑分区 DDR0 (通用)       │
│  │ 0x8000_0000   │                              │
│  │     到        │  大小: 1GB                    │
│  │ 0xBFFF_FFFF   │                              │
│  ├───────────────┤  ← 逻辑分区 DDR1 (显示)       │
│  │ 0xC000_0000   │                              │
│  │     到        │  大小: 512MB                  │
│  │ 0xDFFF_FFFF   │                              │
│  ├───────────────┤  ← 逻辑分区 DDR2 (编码)       │
│  │ 0xE000_0000   │                              │
│  │     到        │  大小: 512MB                  │
│  │ 0xFFFF_FFFF   │                              │
│  └───────────────┘                              │
│                                                 │
└─────────────────────────────────────────────────┘
```

### 为什么叫"平台物理内存"？

```c
typedef struct tagHwifMemBufSt
{
    UINT32  uDdrId;      /* 平台物理内存片/内存池所在的DDR序号，范围0-3 */
    UINT32  uTotalLen;   /* 占用内存总长度 */
    VOID   *pVirAddr;    /* 虚拟地址 */
    VOID   *pPhyAddr;    /* 物理地址 */
    UINT32  reserved[10];     
}HWIF_MEM_BUF_ST;
```

**"平台"** = 海康的嵌入式平台（NT Linux 系统）
**"物理内存"** = 实际 DDR 上的物理地址空间，不是虚拟地址

**核心含义**：在**这个特定平台**上，把 DDR 物理内存**按用途划分**成不同的**逻辑区域**（内存池），每个区域有独立的物理地址范围。

### 为什么这样设计？

```
没有分区（传统 Linux）：
┌────────────────────────────────────┐
│         统一内存池                  │
│  视频编码 ──┐                      │
│  显示渲染 ──┼── 竞争同一块内存 ──→ 带宽瓶颈
│  算法处理 ──┘                      │
└────────────────────────────────────┘

分区设计（海康平台）：
┌────────────┬────────────┬────────────┐
│ DDR0 通用  │ DDR1 显示  │ DDR2 编码  │
│            │            │            │
│ 算法处理   │ GPU 渲染   │ 编码器     │
│ 普通缓存   │ 显示帧缓存  │ 参考帧     │
└────────────┘────────────┴────────────┘
      ↑            ↑            ↑
      │            │            │
   独立带宽    独立带宽     独立带宽
   互不干扰    互不干扰     互不干扰
```

**优势**：

1. **带宽隔离**：编码器不会抢占 GPU 的 DDR 带宽
2. **延迟保证**：显示内存始终有足够带宽，不会花屏
3. **物理连续**：MMZ 区域保证算法需要的大块连续物理内存

## 流媒体场景下的内存管理

### 客户端内存管理

```
┌─────────────────────────────────────────────────────────┐
│                    流媒体客户端                           │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  网络接收                                                │
│  ┌──────────┐                                          │
│  │ Socket   │  ← 接收网络数据包                          │
│  │ 缓冲区   │     (内核态, 通常 64KB-256KB)              │
│  └────┬─────┘                                          │
│       │                                                 │
│       ↓                                                 │
│  ┌──────────────────────────────────────┐              │
│  │        环形缓冲区 (Ring Buffer)        │              │
│  │  ┌───┬───┬───┬───┬───┬───┬───┬───┐  │              │
│  │  │ 0 │ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │ 7 │  │  3-5秒缓冲  │
│  │  └───┴───┴───┴───┴───┴───┴───┴───┘  │              │
│  │   ↑写指针                    ↑读指针  │              │
│  └──────────────────────────────────────┘              │
│       │                                                 │
│       ↓                                                 │
│  ┌──────────────────────────────────────┐              │
│  │         解码缓冲区                     │              │
│  │  ┌────────┐  ┌────────┐              │              │
│  │  │ 参考帧  │  │ 输出帧  │              │  几MB-几十MB│
│  │  │ (YUV)  │  │ (YUV)  │              │              │
│  │  └────────┘  └────────┘              │              │
│  └──────────────────────────────────────┘              │
│       │                                                 │
│       ↓                                                 │
│  ┌──────────────────────────────────────┐              │
│  │         渲染缓冲区 (显示)              │              │
│  │  ┌────────┐  ┌────────┐              │              │
│  │  │ 前缓冲  │  │ 后缓冲  │              │  双缓冲     │
│  │  │ (显示)  │  │ (渲染)  │              │  避免撕裂   │
│  │  └────────┘  └────────┘              │              │
│  └──────────────────────────────────────┘              │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 客户端内存分配策略

```c
// 客户端典型内存配置
typedef struct {
    // 1. 网络接收缓冲
    #define NET_BUF_SIZE    (256 * 1024)    // 256KB

    // 2. 抖动缓冲 (Jitter Buffer)
    #define JITTER_BUF_SIZE (3 * 1024 * 1024) // 3MB, 缓冲3秒

    // 3. 解码缓冲
    #define DECODE_BUF_SIZE (1920 * 1080 * 3 / 2 * 5) // 5帧 YUV420

    // 4. 渲染缓冲
    #define RENDER_BUF_SIZE (1920 * 1080 * 4 * 2) // 双缓冲 RGBA
} ClientMemConfig;
```

### 服务端内存优化技术

```
1. sendfile() 零拷贝
┌────────────────────────────────────────────┐
│ 传统方式 (4次拷贝):                         │
│ 磁盘 → Page Cache → 用户空间 → Socket → 网卡│
│                                              │
│ sendfile() (2次拷贝):                        │
│ 磁盘 → Page Cache ──────────────→ Socket → 网卡│
│         ↑                        ↑           │
│         └── DMA 拷贝 ────────────┘           │
└────────────────────────────────────────────┘

2. 内存池预分配
┌────────────────────────────────────────────┐
│ 固定大小内存池:                              │
│ ┌───┬───┬───┬───┬───┬───┬───┬───┐         │
│ │ 4K│ 4K│ 4K│ 4K│ 4K│ 4K│ 4K│ 4K│         │
│ └───┴───┴───┴───┴───┴───┴───┴───┘         │
│ ┌───────┬───────┬───────┬───────┐         │
│ │ 16K   │ 16K   │ 16K   │ 16K   │         │
│ └───────┴───────┴───────┴───────┘         │
│ ┌───────────────┬───────────────┐         │
│ │ 64K           │ 64K           │         │
│ └───────────────┴───────────────┘         │
│ 避免频繁 malloc/free                        │
└────────────────────────────────────────────┘
```

### 客户端 vs 服务端内存对比

| 维度       | 客户端         | 服务端                     |
| -------- | ----------- | ----------------------- |
| **内存大小** | 几十MB        | 几GB-几十GB                |
| **缓冲策略** | 抖动缓冲 (3-5秒) | Page Cache (GB级)        |
| **关键优化** | 解码缓冲、渲染缓冲   | 零拷贝、内存池                 |
| **内存压力** | 解码器内存占用大    | 并发连接数决定                 |
| **释放策略** | 播放完立即释放     | LRU 缓存淘汰                |
| **典型技术** | Ring Buffer | sendfile() + Page Cache |

### 海康平台流媒体内存特点

```c
// 海康摄像头/录像机作为流媒体服务端
// 结合之前的 HWIF 内存管理

// 视频帧使用平台内存池
HWIF_MEM_ATTRI_ST stAttr;
stAttr.uDdrId = 2;                    // 编码专用 DDR
stAttr.uUseType = MEM_USE_TYPE_VENC;  // 编码用途
stAttr.uMemType = HWIF_MEM_TYPE_NONCACHE; // 硬件编码器直接访问

// 网络发送使用 sendfile 或 DMA 直接发送
// 避免 CPU 拷贝视频帧到网络缓冲区
```

**总结**：客户端关注**解码和渲染**的内存管理，服务端关注**并发和零拷贝**的内存优化。海康平台通过 HWIF 统一管理硬件内存池，实现高效的流媒体处理。
