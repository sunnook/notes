在 Linux 系统中，`/proc/[pid]/maps` 和 `/proc/[pid]/smaps` 都是用于查看进程内存映射的文件，但提供的信息详细程度不同：
- **区别**：
  - `maps` 文件只提供内存映射的基本信息，如地址范围、权限、偏移量等，格式简洁，每行对应一个内存区域。
  - `smaps` 文件则基于 `maps` 的每个区域，提供详细的内存使用统计，如大小、RSS（Resident Set Size）、PSS（Proportional Set Size）等，每个区域会占用多行。
- **联系**：
  - `smaps` 是 `maps` 的扩展版本，两者都描述同一进程的内存布局。`smaps` 中的基本行（如地址范围）与 `maps` 中的行对应，但添加了额外的内存指标。
  - 通常，`maps` 用于快速查看内存映射概览，而 `smaps` 用于深入分析内存消耗，如排查内存泄漏或优化性能。

| 部分 | 含义 |

| `-o` | 指定挂载选项（options） |
| `remount` | 重新挂载（不改动挂载点，只改选项） |
| `,rw` | 设置为读写模式（read-write） |
| `/home/hik` | 要重新挂载的目标挂载点 |

**整体意思**：

---

### **为什么还要加 `,rw`？**

`remount` 只是告诉系统“重新挂载这个挂载点”，但**不指定新的选项**。  
如果不加 `,rw`，系统会使用**原有选项**（即原来的只读 `ro`），那就等于什么都没做。

所以必须显式指定 `,rw` 来覆盖原来只读的状态。

---

### **完整命令对比**

| 命令 | 效果 |
|------|------|
| `mount -o remount /home/hik` | 用原有选项重新挂载（还是只读） |
| `mount -o remount,rw /home/hik` | 重新挂载为读写 |

---

1. 内核收到 `remount` 请求
2. 检查 `/home/hik` 对应的设备（`/dev/mmcblk2p6`）
3. 用新的选项 `rw` 替换旧的 `ro`
4. 重新挂载文件系统，不中断正在使用的进程

`-o` 后面可以跟多个选项，用逗号分隔：

这里 `remount` 和 `rw` 是两个独立的选项，用逗号连接。
