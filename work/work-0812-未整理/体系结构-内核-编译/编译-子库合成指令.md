## `-ffunction-sections -fdata-sections` 的作用

这两个选项的作用是：
- **`-ffunction-sections`**：将每个函数放在独立的段（section）中
- **`-fdata-sections`**：将每个数据变量放在独立的段中

## 为什么放在子库编译中

### 1. **子库编译时**
```bash
# 子库编译时使用
CFLAGS="-ffunction-sections -fdata-sections ..."
```
- 将子库的每个函数和数据独立分段
- 生成的 `.o` 文件和 `.a` 静态库中，函数和数据是分离的
- 这样母库链接时可以选择性地只链接实际使用的函数

### 2. **母库链接时**
```bash
# 母库链接时使用对应的链接选项
LDFLAGS="-Wl,--gc-sections"
```
- 链接器通过 `--gc-sections` 移除未使用的段
- 如果没有在子库编译时使用 `-ffunction-sections`，链接器无法进行段级别的垃圾回收

## 完整的工作流程

```bash
# 第一步：编译子库（使用分段编译）
export CFLAGS="-ffunction-sections -fdata-sections -fPIC ..."
./configure --host=arm-linux --enable-static
make
# 生成 libsub.a，内部函数和数据已分段

# 第二步：编译母库（链接时进行段回收）
export LDFLAGS="-Wl,--gc-sections"
gcc $(LDFLAGS) -o libmain.so main.o -lsub ...
# 链接器会自动移除子库中未使用的函数和数据
```

## 总结

- **`-ffunction-sections -fdata-sections`**：编译选项，放在**子库编译阶段**
- **`-Wl,--gc-sections`**：链接选项，放在**母库链接阶段**
- 两者配合使用才能达到减小最终库体积的效果

如果只在母库编译时使用 `-ffunction-sections`，只能对母库自己的代码进行分段，无法对子库的代码进行分段回收。

## 链接选项的放置规则

### 1. **`-pie` 和 `-s` 的放置**

这两个选项**只能放在最终可执行文件或动态库的链接阶段**：

```bash
# ❌ 错误：编译子库静态库时使用
gcc -pie -s -c sub.c -o sub.o  # 无效，这些是链接选项

# ✅ 正确：编译子库时不用
gcc -c sub.c -o sub.o  # 编译阶段

# ✅ 正确：链接母库（动态库）时使用
gcc -pie -s -shared -o libmain.so main.o -lsub
```

**原因：**
- `-pie`：生成位置无关可执行文件，只在链接最终程序时有效
- `-s`：去除符号表，只在链接阶段有效

### 2. **`-Wl,--gc-sections` 的放置**

这个选项**只在母库链接阶段使用**：

```bash
# ❌ 错误：编译子库时使用
gcc -Wl,--gc-sections -c sub.c  # 无效

# ✅ 正确：链接母库时使用
gcc -Wl,--gc-sections -shared -o libmain.so main.o -lsub
```
