在 `getopts` 循环中处理完参数后，**仍然可以通过 `"$@"` 将剩余参数传递给子脚本**。但您当前的代码有两个问题需要修复：

### 问题分析
1. **参数值获取错误**：
   ```bash
   PLATFORM="$OPT"  # ❌ 错误！应该使用 $OPTARG
   ```
   `$OPT` 存储的是**选项字母**（如 `p`），`$OPTARG` 才存储**选项值**（如 `F5Plus`）

2. **参数位置未重置**：
   `getopts` 处理后会移动参数位置，需要使用 `shift` 重置

### 修复方案
```bash
#!/bin/bash

# 默认值
PLATFORM="F5Plus"  # 设置平台默认参数

# 使用 getopts 解析参数
while getopts 'p:c:h:' OPT  # 注意冒号表示需要参数值
do
    case $OPT in
        p)
            PLATFORM="$OPTARG"  # ✅ 正确获取参数值
            ;;
        c)
            # 其他参数处理
            ;;
        h|?)
            echo "用法: $0 [-p 平台] [-c 配置]"
            exit 0
            ;;
    esac
done

# 关键：移动已处理的参数
shift $((OPTIND - 1))

echo "当前平台: $PLATFORM"
echo "剩余参数: $@"

# 调用子脚本并传递所有剩余参数
if [ -x "build.sh" ]; then
    ./build.sh "$@" || { 
        echo "子脚本build.sh执行失败" 
        exit 1
    }
else
    echo "请先赋予执行权限: chmod +x build.sh"
    exit 1
fi
```

### 关键说明：
1. **`shift $((OPTIND - 1))`**：
   - `OPTIND` 是 `getopts` 的内部计数器
   - 这行代码移除已处理的选项参数，使 `"$@"` 只包含剩余参数

2. **参数传递流程**：
   ```bash
   # 调用父脚本
   ./parent_script.sh -p F5Plus -c config.txt file1 file2
   
   # 父脚本内：
   #   getopts 处理 -p 和 -c
   #   shift 后 "$@" 包含 file1 file2
   #   子脚本接收: ./build.sh file1 file2
   ```

3. **保留原始参数**：
   如果想传递所有原始参数（包括已处理的选项），删除 `shift` 行：
   ```bash
   # 不执行 shift
   ./build.sh "$@"  # 传递所有原始参数
   ```
