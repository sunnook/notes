## 一、带宽隔离和延迟保证的底层原理

### 关键认知：这不是软件层面的隔离，而是硬件层面的

```
错误理解：
  不同地址 = 互不影响
  0x80000000 和 0xC0000000 只是地址不同，但都在同一根总线上！

正确理解：
  隔离的关键是 DDR 控制器（DDRC）和总线矩阵的硬件设计
```

### 为什么能做到带宽隔离？

```
场景：编码器 + 显示同时工作

没有隔离（共享 DDRC）：
┌──────────┐     ┌──────────┐
│ 编码器    │     │ 显示引掣 │
│ 需要 2GB/s│     │ 需要 1GB/s│
└────┬─────┘     └────┬─────┘
     │                │
     └────────┬───────┘
              │
     ┌────────┴────────┐
     │   DDRC 单一     │  → 最大带宽 3GB/s
     │   控制器        │     编码器抢占 2GB/s
     └────────┬────────┘     显示只剩 1GB/s
              │              刚好够！但无余量！
     ┌────────┴────────┐
     │   DDR 颗粒      │     如果编码器突发到 2.5GB/s
     │   共用          │     → 显示欠载 → 花屏！
     └─────────────────┘

有隔离（独立 DDRC）：
┌──────────┐     ┌──────────┐
│ 编码器    │     │ 显示引掣 │
│ 需要 2GB/s│     │ 需要 1GB/s│
└────┬─────┘     └────┬─────┘
     │                │
     │                │
┌────┴─────┐     ┌────┴─────┐
│ DDRC 2   │     │ DDRC 1   │
│ 独立 3GB/s│    │ 独立 3GB/s│  → 各自独占带宽
└────┬─────┘     └────┬─────┘
     │                │
┌────┴─────┐     ┌────┴─────┐
│ DDR 颗粒 │     │ DDR 颗粒 │
│ 编码专用 │     │ 显示专用 │
└──────────┘     └──────────┘

编码器用满 3GB/s 也不影响显示！
```

### 延迟保证的数学原理

```
共享 DDRC 的延迟分析：
┌──────────────────────────────────────────────────┐
│ 最坏情况延迟 = 队列深度 × 单次访问时间      │
│                                            │
│  队列深度 = 64 (编码器占满)                  │
│  单次访问 = 50ns (DDR4)                     │
│  最坏延迟 = 64 × 50ns = 3.2μs               │
│                                            │
│  但实际更差：                                │
│  - 编码器可能连续发起 1000 次访问            │
│  - 显示请求被排到最后                       │
│  - 实际延迟可能达到 100μs+                  │
│  - 对于 60fps 显示 (16.6ms/帧)              │
│    100μs 延迟已可能导致帧丢失             │
└──────────────────────────────────────────────────┘

独立 DDRC 的延迟分析：
┌──────────────────────────────────────────────────┐
│ 显示 DDRC 队列深度 ≈ 2-5                   │
│ 最坏延迟 = 5 × 50ns = 250ns               │
│ 延迟确定且极低                              │
│                                            │
│ 即使编码器 DDRC 满载                        │
│ 显示 DDRC 完全不受影响                      │
└──────────────────────────────────────────────────┘
```

```
┌──────────────────────────────────────────────────┐
```

```
│  │ 硬件编码器: 需要物理连续内存                 │        │
│  │ 显示: 需要带宽隔离                          │        │
│  │ 策略: BSP 内存池 + HWIF 抽象                │        │

│  └──────────────────────────────────┘        │
│                                                          │
│  通用服务器 (Nginx/SRS):                                 │
│  ┌──────────────────────────────────┐        │
│  │ 内存: 64GB - 512GB (可扩展)                 │        │
│  │ 无硬件编码器: 纯软件处理                     │        │
│  │ 无显示需求: 不需要带宽隔离                   │        │
│  │ 策略: Page Cache + sendfile()              │        │
│  │ 并发: 10000+ 连接，动态分配缓冲             │        │

│                                                          │

```

### 总结

| 问题         | 答案                                                |
| ------------ | --------------------------------------------------- |
| 带宽隔离原理  | **硬件层面**：独立 DDRC 控制器 + 独立总线 + 独立 DDR 颗粒           |
| 延迟保证原理  | **队列深度小**：独立 DDRC 队列不会被其他 Master 占满               |
| 服务端内存策略 | **不依赖 BSP**：通用服务器无硬件加速器，用 Page Cache + sendfile() |
| 分布式内存   | **分层缓存**：边缘节点大量 Page Cache，源站大量磁盘，CDN 分发          |
