## vpn协议简介
linux支持2种官方的vpn协议，一个是**wireGuard**,一个是**openVpn**；
wireGuard 运行在内核态，代码精简，性能好吞读量高，仅支持udp，配置简单；
openVpn 运行在用户态（也有内核加速模块），数万行代码，同时支持tcp和udp；

- WireGuard 的 TCP 穿透：原生只有 UDP，但可通过 udp2raw、wstunnel 等第三方工具做 TCP/WebSocket 伪装

对比表格如下：

| 维度 | WireGuard | OpenVPN |
|------|-----------|---------|
| **设计哲学** | 极简、现代、默认安全 | 成熟、灵活、高度可配置 |
| **代码规模** | ~4000 行（内核实现），易审计 | 数十万行（含 OpenSSL 依赖），审计难度大 |
| **运行层级** | 内核态（Linux 5.6+ 内置） | 用户态为主；2.6+ 可选 DCO 内核模块加速 |
| **性能表现** | 高吞吐、低延迟、多核扩展性好，移动端更省电 | 中等；用户态有上下文切换开销，DCO 后接近 WireGuard |
| **加密套件** | 固定且现代：ChaCha20-Poly1305 / AES-24-GCM、Curve25519、BLAKE2s、SipHash24；**不可协商** | 可协商：支持 AES、ChaCha20、3DES 等多种算法；配置不当可能引入弱密码 |
| **传输协议** | 仅 UDP | UDP + TCP（TCP 模式可穿透严格防火墙，但性能损耗大） |
| **连接模型** | 无状态，不区分"连接/断开"，网络切换漫游极快（毫秒级） | 有状态连接，切换网络需重连（秒级） |
| **配置复杂度** | 极简：交换公钥 + 分配 IP，几行配置完成 | 繁琐：需 CA、证书、DH 参数、tls-auth 等 |
| **防火墙穿透** | 弱：单一 UDP 端口，易被深度包检测识别 | 强：支持 TCP 443 伪装、HTTP 代理、shadowsocks 级联等 |
| **生态与兼容** | 主流平台均支持；极老旧系统需额外内核模块 | 历史悠久，几乎所有平台都有客户端，特殊网络环境适配丰富 |
| **适用场景** | 追求性能、简洁、现代架构的常规 VPN 部署 | 复杂网络环境、需 TCP 伪装、老旧系统兼容、高度定制化需求 |

### 为什么说WireGuard仅支持udp--切入vpn技术原理

对于 wireguard, 就需要只走 udp 封装所有数据， tcp 连接也经过 udp 封装！
**本机所有TCP流量（网页HTTP/HTTPS、SSH、文件传输等），全部会被装进WireGuard的UDP数据包里传输到服务端**。
分层逻辑从上到下拆解：
#### 1. 完整数据包封装流程（WireGuard侧）
1. 你的电脑发起普通TCP请求（比如访问网站：TCP 80/443）
2. 操作系统内核把这段TCP报文，交给WireGuard虚拟网卡（wg0）
3. WireGuard **在内核态将整段TCP payload完整加密**，打包成一个UDP报文（固定你配置的WireGuard端口，默认51820/UDP）
4. 这个UDP包通过本地物理网卡、公网发送到VPN服务器
5. 服务端收到UDP包 → 解密 → 取出内部原本的TCP报文 → 代你访问互联网目标地址
6. 回程数据逆向封装：外网返回TCP数据 → 服务端加密打包UDP → 传回客户端 → 解封装恢复TCP数据给到你的电脑

简言之：
> 上层TCP应用流量 = 内层载荷；WireGuard外层永远套UDP头部传输
> **全程不存在WireGuard原生TCP模式**

#### 2. 关键细节区分
**（1）内部TCP ≠ 外层传输协议**
- 你浏览器、SSH、FTP用的TCP：是**应用层之间通信协议**，负责可靠传输、重传、拥塞控制；
- WireGuard外层UDP：只是VPN隧道的**承载传输层协议**，无可靠保障；
隧道丢包处理逻辑：
内层TCP会自己检测丢包、超时重传，不受外层UDP影响。

**（2）为什么WireGuard执意只用UDP？**
1. VPN隧道如果外层用TCP（TCP over TCP）会产生**TCP嵌套灾难（TCP meltdown）**
   两层TCP同时做拥塞控制、超时重传，网络轻微抖动就会大幅卡顿、延迟暴涨、吞吐暴跌；
2. UDP无拥塞控制，交给内层业务TCP全权管控，延迟、吞吐表现最优；
3. 内核实现轻量化，适配手机、嵌入式设备省电需求。

#### 3. 想要WireGuard走TCP隧道该怎么办？（原生不支持，只能套壳）
如需绕过封禁、只能放行TCP端口的严苛网络环境，只能用第三方工具二次封装：
`WireGuard流量 → UDP → wstunnel/udp2raw/socat → TCP报文 → 服务端解包 → 送入WireGuard`
弊端：
- 出现TCP over TCP嵌套，网络波动时性能大幅下滑；
- 多一层封装，额外开销、延迟增加。

#### 4. WireGuard对比 OpenVPN 便于理解
OpenVPN提供两种原生模式可选：
1. UDP模式：和WireGuard逻辑一致（推荐，性能好）
2. TCP模式：整段VPN载荷封装在TCP里传输，天生自带TCP嵌套缺陷，仅作翻墙妥协方案

#### 5. 精简总结
1. 本机所有TCP/UDP应用流量，都会被WireGuard加密封装在外层UDP数据包中传输；
2. WireGuard无原生TCP隧道；
3. 不得已套TCP外壳会触发TCP嵌套，性能受损。

默认选 **WireGuard**（快、简单、安全基线高）；只有在需要 TCP 穿透、老旧系统兼容或强定制加密策略时，才选 **OpenVPN**。



## vpn客户端介绍

对于不同的vpn协议，会有对应的客户端进行支持；我尝试了protonVpn（支持openVpn）和（支持wireGuard）
### ProtonVpn的鸡生蛋问题--切入vpn业务原理
我在win11上下载了protonVpn GUI安装包（linux版），并申请了账号；
遇到的问题是，在ubuntu上，GUI启动，必须访问api.protonvpn（海外接口）做登录账号；
但是，在建立protonVpn的隧道之前，我又访问不了**海外接口**，于是就卡死了；
#### ① 官方GUI为什么坑（鸡生蛋根源）
GUI工作流程：
1. GUI启动，**必须访问 `api.protonvpn.com`（海外接口）做账号登录、拿token、拉服务器列表**，而这个接口，国内裸网访问不到（vpn建立后的那个隧道服务器，国内是可以访问的）。
2. **Linux版Proton‑GUI不读取系统的http_proxy / socks5环境变量**，它内部网络逻辑硬编码，无视系统代理设置。
哪怕你系统Clash全局代理开满，GUI登录请求依然裸网直连api，裸网访问失败，直接登录失败。

> 两种补救GUI登录：
> - 干脆不用GUI，用ovpn手动模式。
> - 或者，用`proxychains4 proton‑vpn‑gui`把GUI整个进程包起来，劫持它TCP登录请求走手机SOCKS代理，完成登录拿到token；token写到本地磁盘；之后关掉proxychains，GUI就可以正常建立VPN隧道。

#### ② 方案A：ovpn配置文件 + openvpn命令行，绕开GUI登录流程
前提：**ovpn文件 + OpenVPN专用账号密码，你要提前在别的能访问外网设备（Windows/手机浏览器）登录Proton网页后台，手动下载导出好**。
步骤：
1. Windows/手机浏览器登录Proton网页后台，
2. 下载OpenVPN‑TCP协议的**ovpn文件**，手动生成并复制**OpenVPN专用用户名密码**。`.ovpn`里面写死：VPN服务器IP、端口、证书、加密参数。
3. 拷贝ovpn文件到Ubuntu；**全程不访问任何Proton API**。
4. 执行`sudo openvpn --config xxx.ovpn`，直接和VPN节点建立OpenVPN隧道，认证只用你本地填写的那套OpenVPN专用账号密码。


 关键点👉：**完全跳过访问api.protonvpn.com登录校验这一步，就没有鸡生蛋死锁**。 
 很多人混淆「网页账号密码」和「OpenVPN专用凭证」；分不清UDP/TCP；以为系统全局代理可以被Proton GUI识别，实际GUI不读取系统代理环境变量。

提醒：
- 只能用**OpenVPN‑TCP版本ovpn**；UDP版本依旧会被国内网络环境干扰；WireGuard的conf配置也不行，WireGuard是UDP，无法借助SOCKS跳板建立隧道。
- ovpn的账号密码≠你网页登录Proton的账号密码，是网页后台单独生成的**OpenVPN凭证**，这点很多人搞错，输错就连不上。
- 补充一个边界：token会过期；ovpn的证书长期有效，但账号凭证也有有效期。
#### ③ 方案B：GUI + Clash代理 + proxychains4
1. `proxychains4 proton‑vpn‑gui`：劫持GUI登录的TCP网络，走**手机SOCKS代理**或**Clash代理**，访问海外api，登录成功，token存入本地磁盘。
2. 关闭proxychains，关掉**手机代理**或**Clash代理**。
3. 正常打开Proton‑GUI，token本地已有，不再需要登录，直接建立VPN隧道。
（**proxychains4见 附录1；走手机sock代理见 附录2**）

注意：proxychains 使用时，也需要先建立好 **外部代理（手机socks，或ubuntu本地Clash）**！
1. proxychains4 仅负责劫持进程TCP套接字流量，自身不具备代理出境能力，必须预先运行 Clash（提供本地SOCKS5监听端口）作为下游出口；
2. 程序流量经 proxychains 转发至本机Clash SOCKS端口，再由Clash完成规则分流、出境转发；
3. 未启动Clash时，proxychains 无可用出口节点，连接会直接超时失败。

仅使用clash，不使用proxychain可不可以？--不可以，Clash全局开了Proton GUI依旧登录失败！
1. 你开了Clash，配置好了系统proxy环境变量
2. `curl、git` 这类工具自动读变量，流量走Clash，可以访问外网
3. Proton GUI走的是**自研网络栈**，**压根不去读取系统proxy变量**
4. GUI发起登录请求：直接裸TCP连接海外认证服务器，国内网络拦截 → 连接超时、登录报错；

#### 5 方案A和B路线对比总结
|方式|要不要访问proton海外api|能不能用SOCKS跳板登录|备注|
|---|---|---|---|
|Proton官方GUI|✅必须访问api拿token|**系统代理无效；只能靠proxychains4包裹整个进程劫持TCP**|GUI功能全，kill‑switch、分流都有，但登录阶段很麻烦|
|openvpn + ovpn文件|❌完全不碰api|不需要登录API；直接连VPN节点|必须提前在别的外网设备下载ovpn与OpenVPN凭证；没有GUI那些高级保护功能|

方案原理总结：
- 登录：访问api.protonvpn.com，拿凭证；裸网下访问失败，需要**跳板代理**帮忙连接，或**提前下载好相关文件**。
- 连 VPN 隧道：访问 VPN 节点服务器；拿到凭证后，本机直接和节点建立加密连接，不再需要跳板代理。
- 上网浏览 GitHub/google：**不再直接访问这些网站，由 VPN 节点代为访问**。


## vpn和代理的区别？
VPN 与 正向代理（SOCKS5/HTTP代理，Clash这类）核心区别对照表
|对比维度|代理（SOCKS5/HTTP 正向代理）|VPN（WireGuard/OpenVPN/ProtonVPN）|
| ---- | ---- | ---- |
|**工作层级**|传输层/应用层（7层）|网络层（3层）|
|**网络原理**|只转发应用程序指定流量；操作系统路由表不变，本机IP栈未被修改|构建完整虚拟网卡，改写系统全局路由，整机所有流量全部纳入隧道封装转发|
|**流量范围**|默认仅读取系统代理变量的软件走代理；终端、部分自研程序不走|整机全部流量：浏览器、终端、软件、系统后台更新、DNS、ICMP数据包均强制经过隧道出口|
|**数据包封装**|**不修改IP包头，仅TCP载荷转发**；外层无完整IP加密封装|原始IP数据包整体加密封装，外层套服务商节点IP，链路私密性更强|
|**跳数逻辑**|标准：**本机 → 本地代理程序 → 海外节点（1跳出境）**<br>可多层链式跳转，但极少使用|基础链路同样1跳直达VPN节点；不依赖多层中转|
|**节点作用**|节点仅做流量中转，不会分配全新虚拟全局公网IP给系统|连接成功后，操作系统完整切换为VPN节点归属IP，对外全网均显示节点IP|
|**UDP支持**|基础SOCKS5无UDP转发能力（proxychains仅劫持TCP）|原生完美支持UDP，流媒体、实时音视频体验更佳|
|**网络隔离与容错**|无系统级断开保护，代理进程崩溃后流量立刻直连本地网络|具备Kill Switch开关：隧道断开瞬间阻断全部外网，杜绝IP泄露|
|**适用场景**|日常浏览网页、拉取代码、轻度外网访问；灵活分流（国内直连、国外走代理）|需要全局网络环境、外网游戏、实时流媒体、整机系统环境切换、追求强隐私安全场景|
|**典型软件**|Clash、Xray、Shadowsocks|ProtonVPN、WireGuard、OpenVPN|
|**短板**|无法全局接管所有流量；隐私防护偏弱|TCP模式存在TCP-over-TCP性能损耗；无法精细化国内网站分流|

**关键补充精简要点**
1. **跳数**：二者常规使用均为**单跳**；代理可手动做多级跳板，VPN几乎不用；
2. **核心本质差异**：代理是**应用层流量中转**；VPN是**建立虚拟专网，替换整机路由网关**；
3. **国内使用痛点**：代理规则分流更适配日常；VPN全局链路适合需要完整海外网络环境的需求。

### 1 代理原理和DNS泄漏
1）本机直连海外IP被防火墙拦截，正向代理服务器身处境外不受限制，替你收发双向网络数据；
安全短板：SOCKS/HTTP代理仅转发应用层数据，无全局数据包加密封装、无路由锁定，极易出现DNS泄露、本机真实IP外泄，隐私安全性弱于标准VPN。

2）DNS泄漏：
域名解析请求（把github.com转为IP）未走加密隧道，仍使用本地运营商DNS解析域名；解析请求明文出境被检测，会暴露你的访问行为与真实网络环境，即便流量走隧道也存在隐私泄露风险；完善VPN自带内置加密DNS，可杜绝该问题。

### 2 正向代理 vs 反向代理
|类型|服务对象|部署位置|核心用途|典型实例|
| ---- | ---- | ---- | ---- | ---- |
|正向代理|面向客户端（上网用户）|用户本地/客户端侧|隐藏客户端IP，突破网络限制、访问外网|Clash、Shadowsocks、SOCKS5|
|反向代理|面向后端业务服务器|网站服务商机房|隐藏后端真实服务器地址，负载均衡、静态资源分发、限流防护|Nginx、CDN、阿里云负载均衡|

一句话区分：
正向代理：**替用户上网**；反向代理：**替网站接待访客**。

#### 1、正向代理极易DNS泄露，并非必然；VPN配置不当也会泄露
- 正向代理（Clash默认规则模式）：浏览器、系统DNS请求不走代理隧道，直接发给国内运营商DNS，**几乎一定会DNS泄露**；只有手动把系统DNS强制指定为代理内置加密DNS才可规避。
- VPN：完整接管系统路由+虚拟网卡，默认所有DNS请求都在隧道内解析，原生不会泄露；仅手动自定义本地DNS、关闭隧道保护时，才会发生泄露。

#### 2、IP隐藏范围区分
1. **仅对目标网站/服务端隐藏你的本机公网IP**
网站日志里记录的是代理/VPN节点IP，看不到你的真实IP；
2. **国内防火墙全程可以观测你的上行链路**
防火墙清楚：你的设备一直在和境外代理/VPN节点持续通信，只是无法解密隧道内传输内容、看不到你具体访问了哪些网页；
IP没有对防火墙隐藏，只是访问内容被加密屏蔽审查。
## 附录1、proxychains4是什么
底层机制：**LD_PRELOAD 注入动态库**，劫持程序内部libc的`connect()` socket系统调用。
> 普通程序：`connect(目标IP,端口)` → 直接往外建socket。
> proxychains4 包裹运行的程序：connect被劫持，**不直连目标，偷偷连你的SOCKS代理地址（手机192.168.5.229:1080），由代理帮你转发流量**。

关键点：
1. **只劫持TCP，UDP完全管不了**。WireGuard主要走UDP，proxychains4对它无效；OpenVPN‑TCP是TCP，所以可以被劫持代理出去。
2. 用法：`proxychains4 curl https://github.com`，**只对当前这一条命令的进程生效，不是系统全局代理**。
3. 局限：只能劫持动态链接的程序；静态编译程序、内核态流量、UDP无能为力。

## 附录2、Socket、HTTP代理、SOCKS5代理三者关系
- **Socket（套接字）**：是操作系统给应用程序的**网络接口API**，相当于水管接口；不管HTTP、SSH、OpenVPN，所有网络程序最终都调用socket的connect/send/recv。
- **HTTP代理（7层应用层）**：只懂HTTP/HTTPS协议；只能转发网页请求；不懂OpenVPN、SSH这类别的协议，通用性差。
- **SOCKS5代理（会话层，贴近传输层）**：**不理解上层协议内容，只转发原始TCP字节流**。不管是网页、HTTPS、SSH、OpenVPN‑TCP，只要是TCP流量，一股脑帮你转发出去，通用性强。所以proxychains统一劫持后都可以走它。

> 通俗比喻：
> socket = 家里自来水接口；
> HTTP代理 = 只认可乐饮料的中转机器，只处理可乐；
> SOCKS5代理 = 通用水管转接器，**任何流体（TCP流量）都可以过**。

## 附录3 OpenVPN‑TCP 是能用，但天生有硬缺陷：TCP‑over‑TCP（TCP 嵌套）问题
### 原理
- 你的本地上网业务本身大多是TCP（浏览器git https）
- 外层OpenVPN隧道又套一层TCP
> 等于：**TCP包，封装进另一个TCP隧道里面传输**。

一旦网络出现丢包：
> 内层业务TCP发现丢包 → 重传；
> 外层OpenVPN的TCP同时也发现同一个包丢包 → 也做一次重传。
双重重传、双重拥塞控制，**网络稍微抖动，延迟暴涨、速度暴跌，甚至卡死假死**。

### 三者对比
1. **OpenVPN‑UDP**：理想
没有TCP嵌套，性能好、延迟低；缺点UDP容易被封，**不能走proxychains4 SOCKS跳板建立隧道**。
2. **OpenVPN‑TCP（443）**：就是你用来绕鸡生蛋的方案
✅优点：TCP，可以被proxychains劫持完成初始登录；443端口不容易防火墙拦截。
❌缺点：**TCP‑over‑TCP灾难，网络质量差时体验拉胯**；不适合语音、实时视频；适合单纯浏览网页、拉github代码。
3. **WireGuard(UDP)**：性能最好，但完全不能借助SOCKS跳板建立隧道，解决不了你“初始登录拿凭证”的死锁问题。

### 放到我的实际场景怎么取舍
1. **仅用来临时救急：拿到token / 拉代码、下载WebRTC源码**，OpenVPN‑TCP完全够用，忍一点性能问题；
2. 如果长期日常使用：拿到token之后，切回WireGuard或者OpenVPN‑UDP；
3. 注意：不要拿OpenVPN‑TCP打音视频、实时性业务，丢包的时候体验会非常糟糕。

### 补充现实坑
Proton的TCP节点速度普遍比UDP慢，晚上高峰会更明显，这就是你记忆里“TCP版本好像有问题”的来源。

> 总结一句话：**OpenVPN‑TCP是解决“连不上”的救命方案，不是追求性能的优选方案**。
能UDP就UDP；只有UDP彻底连不通、或者需要借助SOCKS跳板初始化的时候，才用TCP。


## 附录4 为什么 WireGuard UDP 协议不能走 SOCKS 代理？
**核心原因**
1. SOCKS5代理**仅标准化支持TCP流量转发，无UDP代理规范**；proxychains4依靠劫持`connect()`系统调用工作，该调用仅用于建立TCP连接，无法劫持UDP无连接套接字。
2. OpenVPN-TCP基于TCP流式套接字，可被劫持后交由SOCKS中转；WireGuard全程使用UDP报文收发，不存在连接握手过程，proxychains完全无法接管，因此不能借助SOCKS跳板建立隧道。

## 附录5 拿到 token 之后，切回 WireGuard 或者 OpenVPN‑UDP--切换UDP两种方式
① **命令行OpenVPN模式：需要重新下载UDP协议后缀的.ovpn配置文件**（TCP、UDP节点端口、参数不一致，配置文件互相不通用）；
② **Proton官方GUI内切换：无需重下.ovpn文件**，本地已有登录Token，直接在客户端协议选项中将TCP改成UDP，选择对应节点即可一键重连。

## 附录6 ubuntu 里代理就是指 Clash 吗？还是有其他？
1. **代理 ≠ Clash**
Clash只是Ubuntu上最流行的**本地代理客户端软件之一**，并非代理本身，也不是系统唯一代理工具。

2. Linux 常见代理分类
#### （1）本地代理内核程序（转发工具）
- Clash/Mihomo：当下主流，规则分流、多协议支持最优
- V2Ray / Xray：早年主流代理工具
- Shadowsocks-libev：极简轻量SOCKS代理

以上程序运行后，都会在本机开放 SOCKS5/HTTP 端口，提供代理出入口。
#### （2）系统层面代理形态
- 环境变量代理（`http_proxy`/`all_proxy`）：系统通用标准，绝大多数软件遵循读取；
- TUN代理：接管整机网卡全部流量，无视软件自身是否兼容代理；
- proxychains4：劫持工具，不属于代理服务，只是强行转发TCP流量到SOCKS端口。

3. 相互关系
任意一款转发软件（Xray/ss/clash）开启后，都能充当本地代理出口；目前只用Clash，所以才会产生等同错觉。

4. 补充区别
- Clash优势：可视化面板、节点切换、国内国外自动分流，新手首选；
- ss/Xray：更轻量化，适合服务器无桌面环境使用。



## 附录7 关于Clash代理
### 1. Clash 本质
运行在你Ubuntu本地的**代理客户端程序**，监听本机 `127.0.0.1:7890/7891` 端口：
- 7890端口：HTTP代理端口
- 7891端口：SOCKS5通用代理端口
功能：接收本机所有软件发来的网络流量，加密中转出境访问海外网站，是Linux最主流的代理工具。

先拆分两个核心东西：**Clash内核（命令行本体）** + **Clash Verge（图形界面外壳）**
### 1、原版 Clash（Mihomo/Clash Meta）是什么？
1. **它本身只是一个Go语言写的命令行程序（二进制可执行文件），并不是Ubuntu自带的系统服务**
   - 原生只有终端运行模式，没有窗口界面；
   - 运行后监听本机 `127.0.0.1:7890(HTTP)`、`127.0.0.1:7891(SOCKS5)`，提供代理端口；
   - 本质：本地流量调度转发引擎，负责把本机网络流量按照规则分流（国内直连、国外走代理出境）。
2. **默认不属于Systemd系统服务**
   你直接在终端启动，关掉终端程序就退出；
   想开机自启、后台常驻，需要自己编写 `systemd` 配置文件，把它注册成系统后台服务才行。
3. **安装不需要大量系统依赖**
   纯静态编译二进制，下载下来直接就能跑；Ubuntu基础环境即可运行。

### 2、Clash Verge 到底是干什么的？（你现在装的这个）
一句话总结：**Clash Verge = 可视化图形窗口界面 + 内置Mihomo代理内核 = 给小白用的一键管理工具**
层级关系：
```
Clash Verge（GUI窗口程序）
    ↓ 调用管理
Mihomo(Clash Meta) 内核（真正干活的代理服务）
```
#### 核心作用：
1. **不用手写复杂yaml配置文件**
   网页订阅链接一键导入节点、切换节点、测速、切换「全局/规则/直连」模式，全部鼠标点一点；
2. **一键开关系统全局代理**
   软件内部按钮开启后，自动帮你写入Linux系统代理环境变量；关闭自动清空；不用每次终端敲一堆`export`命令；
3. **常驻托盘后台**
   最小化缩到桌面右上角状态栏，随时启停代理，查看流量、日志；
4. **持续维护更新**
   原版Clash作者删库停更，现在主流都用 **Clash Verge Rev 迭代版本**，支持VLESS、Hysteria2等新型代理协议，Linux Ubuntu适配完善。

#### 通俗比喻：
- Mihomo内核 = 空调外机（真正制冷干活的核心）
- Clash Verge = 室内控制面板屏幕（调温度、模式、开关机，人交互用的外壳）

### Clash 算不算Ubuntu系统服务？两种运行模式区别
#### 模式1：通过Clash Verge图形界面启动（你日常在用的）
- 属于**用户级桌面应用进程**，不是系统级后台服务；
- 登录桌面后软件才会运行，注销/关机就结束；
- 优点：简单易用，随手开关；缺点：无桌面服务器环境没法用。

#### 模式2：手动配置systemd，注册为系统后台服务
把Clash内核做成开机自启的系统服务，无桌面服务器也能后台一直跑；
适合长期挂机、Ubuntu服务器使用，普通桌面用户没必要折腾。

### 三、结合之前ProtonVPN的问题，串起来逻辑
1. 打开 **Clash Verge** → 开启「系统代理」全局模式
   终端`curl、git、wget、浏览器`都会读取系统`http_proxy/all_proxy`变量，流量走Clash出境访问外网；
2. **但是Proton Linux GUI客户端不遵守系统代理变量**
   它内部网络代码硬编码直连海外认证服务器，所以哪怕Clash全局全开，GUI依旧登录失败；
3. 解决方案二选一：
   ① `proxychains4 proton-vpn-gui` 强制劫持GUI所有TCP流量走Clash/SOCKS代理，临时登录拿到本地token；
   ② 网页端提前下载`.ovpn`配置文件，绕开GUI登录流程，直接用openvpn命令连接VPN。

### 四、关键常见疑问解答
### 1、开启系统代理之后，终端为什么还要手动export变量？
- Clash Verge开启的**系统代理**，只作用于**桌面环境（GUI程序、浏览器）**；
- Ubuntu终端是独立会话，不会自动继承桌面代理变量，所以需要手动export，或者写入`~/.bashrc`永久生效。
#### 2、TUN模式是什么？
进阶模式：直接接管整机所有网卡流量，所有程序（包括不读系统代理的软件）全部强制走代理；
缺点：需要sudo管理员权限，容易和VPN软件冲突，日常用「系统代理」就足够。
### 五、极简使用流程（Ubuntu）
1. 打开Clash Verge软件；
2. 导入订阅链接，选择一个延迟最低的节点；
3. 开启：**系统代理 + 规则模式**；
4. 终端按需配置proxy环境变量即可访问外网；
5. 用完关闭系统代理，退出软件。

## 附录9 https_proxy /socks5 环境变量
### 1. 基础概念
Linux 系统约定了一套**全局标准环境变量**：
```bash
# http/https网页代理
export http_proxy="http://127.0.0.1:7890"
export https_proxy="http://127.0.0.1:7890"
# 通用socks5代理（所有TCP流量走这里）
export all_proxy="socks5://127.0.0.1:7891"
```
作用：
绝大多数**开源命令行工具、标准网络库编写的程序**（`curl`、`wget`、git、Python、Firefox浏览器），发起网络请求前，会**自动读取这几个变量**，流量自动转给代理中转出境。

举例子：
你终端执行 `curl https://github.com`
程序发现系统配置了proxy变量 → 流量自动走Clash代理 → 成功访问外网。

### 2. 关键：不是所有软件都会读这套变量！分两类软件
✅ **会读取系统代理变量（绝大多数常规软件）**
curl、wget、git、Chrome/Firefox、Python/Java写的程序、大部分开源小程序

❌ **不会读取系统环境变量（ProtonVPN Linux GUI就是这类）**
Proton官方Linux桌面客户端，开发时：
1. **自己手写了一套独立网络请求代码**，没有调用系统标准网络库；
2. 代码里**硬编码写死：直接裸网连接api.protonvpn.com**，全程不检查系统有没有配置http_proxy、all_proxy；
3. 哪怕你Clash全局开满、变量全部配置正确，它完全无视，依旧直连海外认证服务器，国内裸网被拦截 → 登录失败。

这就是那句话的完整含义：
> Linux版Proton-GUI不读取系统的http_proxy /socks5 环境变量，内部网络逻辑硬编码，无视系统全局代理。
### 3. Ubuntu下完整打开&开启全局代理步骤
#### 步骤1：后台启动Clash服务
```bash
# 1. 启动Clash（根据你安装的文件名调整）
clash-linux-amd64 -d ~/.config/clash/
# 加&放到后台运行，关闭终端不退出
clash-linux-amd64 -d ~/.config/clash/ &
```
#### 步骤2：终端开启全局代理（临时生效，仅当前终端窗口）
```bash
# 一键设置全局代理变量
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
export ALL_PROXY=socks5://127.0.0.1:7891
# 小写变量兼容部分老旧程序
export http_proxy=http://127.0.0.1:7890
export https_proxy=http://127.0.0.1:7890
export all_proxy=socks5://127.0.0.1:7891
```
#### 步骤3：验证代理是否生效
```bash
# 查看当前出口IP，出现海外IP=代理成功
curl ip.sb
```
#### 步骤4：关闭代理
```bash
# 清空代理环境变量
unset HTTP_PROXY HTTPS_PROXY ALL_PROXY http_proxy https_proxy all_proxy
# 杀掉后台Clash进程
pkill clash-linux-amd64
```


## 附录10 关于Proton vpn--鸡生蛋‑蛋生鸡 详解
> 问题复述：
ProtonVPN客户端**登录校验必须访问它海外的认证服务器**，这个服务器本身在墙外。
正常国内裸网：连不上认证服务器 → 登录失败，VPN隧道起不来，也就不能翻墙。

> 但：**先用另外一个代理（你手机SOCKS代理），让客户端的登录网络走这个代理，认证请求就出去了；账号校验完成之后，就可以关掉这个代理，启用ProtonVPN自己的隧道。**

这里关键要分清**两段完全独立的网络通路**，很多人把两者混在一起，就想不通。

### 1、登录阶段（账号校验阶段）
- ProtonVPN GUI/CLI 做登录：只是发普通HTTPS请求，访问 `api.protonvpn.com`，做账号密码校验、拿服务器列表、拿配置。
- **这个登录请求，可以交给别的代理（proxychains4 / clash）转发出去**。
- 此时：**真正的ProtonVPN隧道还没有建立！还没有任何VPN加密通道**。
> 流量路径：Ubuntu本机 → 你的手机SOCKS代理 → 外网 → Proton认证服务器
✅认证成功，本地拿到：token、可用VPN节点列表、密钥。**这些凭证保存在本机磁盘上**。

👉 到此为止，**你已经不需要手机代理了，账号凭证已经存在你电脑本地**。

### 2、真正VPN连接阶段（建立OpenVPN/WireGuard隧道）
拿到凭证之后，ProtonVPN客户端发起建立 **OpenVPN / WireGuard隧道**。
> 这一步流量**不再走刚才那个手机代理**。
流量路径：Ubuntu本机 —(原生UDP/TCP)—> Proton的海外VPN节点服务器。
隧道建立成功之后，**系统全部流量走这条VPN隧道访问互联网**。

### 为什么不会卡死？
1. **认证、隧道建立，是两个独立步骤**。
2. 你只需要“短暂借助外部代理完成第一步账号校验，拿到本地token凭证”。
3. token存本地磁盘，校验完成，辅助代理就可以撤掉。
4. 后续由ProtonVPN自己的VPN协议（OpenVPN‑TCP/UDP）直接和海外节点通信。

> 逻辑顺序：
> ①借助跳板代理完成账号认证 →②把授权token保存本机 →③销毁跳板代理 →④本机直接发起VPN协议连接Proton节点 →⑤全部流量走VPN隧道。

### 那为什么大家都说ProtonVPN有鸡生蛋问题？
- Proton官方GUI**默认并不支持系统代理 /socks代理**。
GUI内部网络请求不走系统全局代理，你就算开了Clash全局，GUI登录请求**无视系统代理**，依旧走裸网，裸网连不上api，直接登录失败。
> 这就是坑：GUI不读取系统代理设置，你系统开代理没用。

两种解决手段：
1. 使用`proxychains4`强制劫持Proton客户端进程的socket，强制登录阶段流量走代理，拿到token；拿到token之后关掉proxychains，正常起VPN隧道。
2. 网页在Windows/手机上登录Proton网站，**提前下载好OpenVPN的ovpn配置文件 + OpenVPN专用账号密码**，直接在Linux用openvpn命令加载ovpn，**完全绕开Proton GUI的登录流程，不需要访问它的api接口**。

### 一个通俗类比
想象你要进一个会所：
- 会所大门（ProtonVPN隧道）本身锁死，必须出示会员卡（token）才能开门进去。
- 但是会员卡要去海外总部办理（访问api.protonvpn.com校验账号）。
- 国内直接寄信去海外总部寄不过去（裸网访问失败）。
- 于是你先找个快递中转（手机SOCKS代理），把你的身份请求通过中转送到海外总部。
- 总部核验通过，寄回会员卡（token，存你电脑本地）。
- 中转快递任务完成，可以扔掉。
- 你拿手里已经拿到的会员卡，直接刷会所大门，会所大门打开，你直接进入会所（VPN隧道）。

> 关键点：**会员卡拿到手之后，就不再需要那个中转快递了。**

### 现实坑点补充
1. token会过期，过一段时间又要重新登录校验，那时候又需要临时跳板代理；
2. WireGuard模式：WireGuard协议本身**不能走socks代理**，所以WireGuard节点不能用proxychains帮忙建立隧道；只能用OpenVPN‑TCP模式；
3. 这也是Mullvad和Proton的差别：Mullvad只需要一串账号码，不需要HTTPS登录API，直接填key就可以建立隧道，理论上不存在这个“登录要外网”的死锁问题，但WireGuard流量本身依旧不能走socks代理跳板。

### 总结一句话
> 鸡生蛋问题卡死，指的是：**登录认证请求无法出境，拿不到授权凭证**。
> 借助代理，只是帮你把“登录认证那一小部分HTTPS请求送出境，拿到本地凭证”；真正的VPN隧道，是凭证到手之后，本机直接跟海外服务器建立的另一套独立加密链路，不再依赖原来的代理。
