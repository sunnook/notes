# GStreamer 流水线生命周期业务表格

> 结构与 LiveKit 表格对应：`应用层(gst-launch/C) → GStreamer C API(核心库) → 底层机制(GObject/GLib/调度)`。
> 行号基于 `gstreamer-1.29.2` 源码，已核对（见 `gs-pip-analysis.md`）。
> 调用链列每层用换行表示。

| 阶段 | 应用层（gst-launch / C 程序） | 调用链 | GStreamer C API 接口 | GStreamer 涉及文件 | 底层机制（GObject/GLib/调度） | 底层涉及文件 | 描述和备注 |
|------|------------------------------|--------|---------------------|-------------------|------------------------------|-------------|-----------|
| **一、准备** | | | | | | | |
| 1. 初始化 GStreamer | `gst_init(&argc, &argv)`<br>`gst_init_check()` | `gst_init`(gst.c:451)<br>→ `gst_init_check`(gst.c:455)<br>→ `_priv_gst_init_seed`<br>→ `gst_init_get_option_group`<br>→ `gst_registry_init`<br>→ `gst_register_core_elements`(gst.c:608) | `gst_registry_init`<br>→ `gst_element_register("bin"/"pipeline", GST_TYPE_BIN/PIPELINE)` | `gst/gst.c`<br>`gst/gstregistry.c`<br>`gst/gstelementfactory.c` | GObject 类型系统初始化；扫描/加载插件 .so（dlopen）；把内置元素工厂注册进全局 registry | `gst/gst.c`<br>`gst/gstregistry.c`<br>`gst/gstplugin.c`<br>`gst/gstpluginloader.c` | 加载 native 库，初始化全局注册表，注册内置元素（bin/pipeline）。工厂名从这里进注册表。 |
| 2. 解析流水线描述 | `gst_parse_launch("filesrc ... ! queue ! fakesink", &err)`（gst-launch 内部） | `gst_parse_launch`<br>→ `gst_parse_launchv`<br>→ 解析器逐 token 构建<br>→ 对每元素 `gst_element_factory_make`<br>→ `gst_bin_add` + `gst_element_link` | `gst_parse_launch`<br>→ `gst_element_factory_make` | `gst/gstparse.c`<br>`gst/gstelementfactory.c` | 递归下降解析器把 `!` 分隔的流水线字符串转成元素图 | `gst/parse/`（parse.l/parse.y） | gst-launch 语法解析，是编程式构建的快捷方式。 |
| 3. 创建元素（工厂实例化） | `gst_element_factory_make("filesrc", "source")` | `gst_element_factory_make`(gstelementfactory.c:819)<br>→ `make_full`(:791)<br>→ `make_valist`(:738)<br>→ `gst_element_factory_find`(查注册表)<br>→ `gst_element_factory_create_valist`(:556)<br>→ `gst_plugin_feature_load`(dlopen)<br>→ `gst_element_factory_create_with_properties`<br>→ `g_object_new` | `gst_element_factory_find`<br>→ `gst_plugin_feature_load`<br>→ `g_object_new` | `gst/gstelementfactory.c`<br>`gst/gstpluginfeature.c`<br>`gst/gstplugin.c` | GObject `g_object_new` 实例化对象，按工厂名查注册表 | `gst/gstelementfactory.c`<br>`gst/gstplugin.c`<br>GLib `gobject/gobject.c` | 查注册表 → 加载插件 → g_object_new 造实例。工厂名是符号，查不到返回 NULL（打 warning，不崩）。 |
| **二、构建流水线** | | | | | | | |
| 4. 添加元素到容器 | `gst_bin_add_many(GST_BIN(pipeline), src, sink, NULL)`<br>→ `gst_bin_add` | `gst_bin_add`<br>→ 挂到 bin 子元素列表<br>→ 处理 ghost pad/时钟/状态 | `gst_bin_add` | `gst/gstbin.c` | 把元素加入 bin 的 children 列表，建立父子关系 | `gst/gstbin.c` | 元素挂到 pipeline 下做子元素。 |
| 5. 连接元素 | `gst_element_link(src, sink)` | `gst_element_link`(gstutils.c:2276)<br>→ `gst_element_link_pads`(:2160)<br>→ `gst_element_link_pads_full`(:1844)<br>→ `pad_link_maybe_ghosting`(:1732)<br>→ `gst_pad_link_full`(gstpad.c:2552)<br>→ `gst_pad_link_prepare`<br>→ `GST_PAD_PEER` 互指<br>→ `schedule_events` + LINKFUNC 回调 | `gst_pad_link_full`<br>→ `gst_pad_link_prepare` | `gst/gstutils.c`<br>`gst/gstpad.c` | 两 pad 在 `GST_PAD_PEER` 互存对方指针；检查方向+caps 兼容；安排 sticky 事件 | `gst/gstpad.c` | **连接的本质 = GST_PAD_PEER 互指**。之后数据流全靠 peer 指针。 |
| 6. 配置元素属性 | `g_object_set(element, "property", value, NULL)`<br>`gst_element_set_property()` | `g_object_set`<br>→ GObject 属性系统<br>→ 元素 set_property 虚函数 | `g_object_set`<br>→ `gst_element_set_property` | `gst/gstelement.c`<br>GLib `gobject/gobject.c` | GObject 属性机制（GParamSpec） | GLib `gobject/` | 设置元素属性（如 filesrc 的 location）。 |
| **三、运行** | | | | | | | |
| 7. 设置状态 | `gst_element_set_state(pipeline, GST_STATE_PLAYING)` | `gst_element_set_state`(gstelement.c:2922)<br>→ `oclass->set_state`<br>→ `gst_element_set_state_func`(:2946)<br>→ 计算 NULL→READY→PAUSED→PLAYING 转换<br>→ 递归子元素 change_state<br>→ 数据源 task 线程启动 | `gst_element_set_state`<br>→ `gst_element_set_state_func`<br>→ `gst_element_change_state` | `gst/gstelement.c`<br>`gst/gsttask.c` | 状态机迁移；每元素 change_state；启动 task 线程 | `gst/gstelement.c`<br>`gst/gsttask.c` | 触发状态切换，开始调度。 |
| 8. 数据流（push/chain） | 元素内部 `gst_pad_push(srcpad, buffer)` / `gst_pad_chain` | `gst_pad_push`(gstpad.c:5008)<br>→ `gst_pad_push_data`(:4840)<br>→ 检查 flushing/EOS/mode/sticky<br>→ 跑 probe(block+普通)<br>→ `peer = GST_PAD_PEER(pad)`<br>→ `gst_pad_chain_data_unchecked(peer)`<br>→ `GST_PAD_CHAINFUNC`(下游)<br>→ 下游再 push → 递归到 sink | `gst_pad_push`<br>→ `gst_pad_chain`<br>→ `gst_pad_chain_data_unchecked` | `gst/gstpad.c` | **无中央调度器**：每个元素主动 push，顺着 peer 指针一站站传 | `gst/gstpad.c` | 数据流心脏。peer 指针 + push/chain 递归是流水线真正跑起来的机制。 |
| 9. 总线消息循环 | `gst_pipeline_get_bus(pipeline)`<br>→ `gst_bus_timed_pop_filtered(bus, timeout, GST_MESSAGE_ERROR\|EOS)` | `gst_pipeline_get_bus`<br>→ `gst_bus_timed_pop_filtered`<br>→ 阻塞等消息 | `gst_bus_timed_pop_filtered`<br>→ `gst_bus_pop` | `gst/gstbus.c`<br>`gst/gstpipeline.c` | Bus 异步消息通道：元素往 bus 发 message，应用阻塞/轮询取 | `gst/gstbus.c` | 处理错误/结束（EOS）消息。 |
| **四、收尾** | | | | | | | |
| 10. 停止 | `gst_element_set_state(pipeline, GST_STATE_NULL)` | 同 set_state 逆向<br>→ PLAYING→PAUSED→READY→NULL<br>→ 停 task 线程 | `gst_element_set_state` | `gst/gstelement.c` | 状态机逆向迁移，停止线程 | `gst/gstelement.c` | 停止播放，释放资源。 |
| 11. 销毁 | `gst_object_unref(pipeline)` | `gst_object_unref`<br>→ 引用计数归零<br>→ GObject dispose/finalize<br>→ 递归释放子元素 | `gst_object_unref`<br>→ `g_object_unref` | `gst/gstobject.c`<br>`gst/gstminiobject.c` | GObject 引用计数 + 析构 | `gst/gstobject.c`<br>GLib `gobject/gobject.c` | 释放整个 pipeline 及所有子对象。 |
