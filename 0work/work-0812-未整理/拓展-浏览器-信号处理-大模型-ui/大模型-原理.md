大模型生成 token 之所以是**“访存密集型”**而不是“计算密集型”，完全是由它的**自回归生成机制**和**底层矩阵运算的数学特征**决定的。

我们可以把原因拆解为以下三个层面来看：

### 1. 机制层面：逐字生成导致的“算力闲置”

大模型生成文本的方式叫**自回归**。意思是，它必须**一个词一个词地往外蹦**，且生成第 N 个词时，必须依赖前面 1 到 N-1 个词的结果。

*   **Prefill 阶段（吃进提示词）：** 当你输入一段 1000 字的提示词时，模型可以**并行**处理这 1000 个字。这时候，GPU 里的计算单元满载运行，一次算出所有 token 的特征。这个阶段是**计算密集型**的，GPU 的算力被榨干了。
*   **Decode 阶段（生成回答）：** 模型开始写回答。写第 1 个字时，算力全开；写完第 1 个字，把结果存起来。写第 2 个字时，必须等第 1 个字算完，再把前面所有的信息重新过一遍模型。**每一次生成一个新 token，都要把整个神经网络（所有参数）完整地跑一遍。**

这就导致了一个致命问题：在 Decode 阶段，**每次计算只处理 1 个 token 的数据量，计算量极小，但为了完成这点计算，必须把几百 GB 的整个模型搬到计算单元里。**

### 2. 数据层面：搬运“整个模型”的沉重代价

这是理解“访存密集”的关键。

假设你有一个 70B 参数的大模型（比如 Llama-3-70B），使用 FP16（半精度浮点数）存储，每个参数占 2 个字节。
*   **模型权重总大小 = 700 亿 × 2 字节 ≈ 140 GB。**

当模型生成**1 个 token** 时，发生了什么？
1.  GPU 的计算核心向显存发出请求：“把第一层的权重发给我”。
2.  显存把第一层权重的数据通过总线传给计算核心。
3.  计算核心做一次矩阵乘法（拿这 1 个 token 的向量 × 第一层权重矩阵）。
4.  算完第一层，结果传回显存。
5.  再请求第二层权重……如此循环，跑完 80 层 Transformer。

**核心矛盾出现了：**
为了生成这 1 个 token，计算核心只做了极其微小的几次矩阵乘法（计算量极低），但它**必须把 140 GB 的权重数据，从显存搬运到计算核心一遍！**

生成第 2 个 token，再搬运 140 GB；生成第 3 个，再搬运 140 GB……
这就好比一个厨师（计算核心），为了切一根葱（1 个 token），每次都要把整个 500 平米冷库（显存）里的所有食材（模型权重）都搬出来看一遍再放回去。厨师切葱的手速再快（算力再强），也赶不上搬食材的时间。**瓶颈全在“搬砖”上。**

### 3. 量化视角：算术强度极低

在计算机体系结构里，衡量一个任务是计算密集还是访存密集，看一个指标：**算术强度**。
*   **算术强度 = 计算量 (FLOPs) / 访存数据量。**

在生成阶段：
*   **计算量：** 对于一个参数量为 $P$ 的模型，生成 1 个 token 的计算量大约是 $2P$ 次乘加运算。
*   **访存量：** 生成 1 个 token，至少需要把所有权重读一遍，访存量就是模型大小 $2P$ 字节（FP16下）。
*   **算术强度 = $2P$ FLOPs / $2P$ Bytes = 1 FLOP/Byte。**

**1 FLOP/Byte 是什么概念？**
现在的 GPU（比如 H100），计算能力是 1000 TFLOPS（每秒 1000 万亿次运算），而显存带宽是 3 TB/s（每秒 3 万亿字节）。
GPU 要发挥满血算力，需要的算术强度是：`1000 TFLOPS / 3 TB/s ≈ 333 FLOP/Byte`。

而大模型生成 token 的算术强度只有 **1**！
这意味着，GPU 的计算能力理论上可以比内存搬运速度快 **333 倍**。所以，计算单元 99.7% 的时间都在干瞪眼等数据送过来。这就是纯粹的**访存墙**。

### 4. 还有一个帮凶：KV Cache 的膨胀

除了模型权重要反复搬运，还有一个东西也要反复读写，那就是 **KV Cache**。

为了不每次都从头计算之前的 token，大模型会把之前算过的每个 token 的 Key 和 Value 矩阵缓存在显存里。
*   随着生成的 token 越来越多，KV Cache 像滚雪球一样变大。
*   在生成新 token 时，不仅要读取巨大的模型权重，还要把巨大的 KV Cache 也读出来进行 Attention 计算。
*   这进一步加剧了内存的读取负担，让“访存密集”雪上加霜。

### 总结

为什么大模型生成 token 是访存密集型任务？

因为**自回归机制**要求每生成 1 个字，都要把**整个模型权重**从内存搬运到计算单元一次，而实际进行的计算量却微乎其微。这导致计算单元处于严重“吃不饱”的状态，任务瓶颈完全卡在了内存到计算单元的数据传输带宽上。

所以：
*   **CPU（DDR5 内存，300 GB/s 带宽）** 搬这 140 GB 的模型需要 0.4 秒，所以每秒只能吐 2-3 个字。
*   **GPU（HBM3 显存，3 TB/s 带宽）** 搬这 140 GB 只需要 0.04 秒，所以每秒能吐几十个字。

大模型推理，拼的不是谁算得快，而是谁把数据搬得快。这就是硬件架构决定性的最完美体现。
