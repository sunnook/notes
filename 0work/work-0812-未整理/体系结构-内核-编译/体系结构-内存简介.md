</think>## Cache 内存 vs Non-Cache 内存

### 什么是 Cache

```
CPU 访问内存的速度差异：

CPU 速度: ~1ns (3GHz)
    ↓ 等待 100-200 个时钟周期
DDR 速度: ~50-100ns

Cache 的作用：
┌─────────────────────────────────────────────┐
│              CPU 缓存层次                     │
│                                             │
│  ┌─────────┐  最快 (1ns)                    │
│  │ L1 Cache│  32KB, 私有                    │
│  └────┬────┘                                │
│       ↓                                     │
│  ┌─────────┐  较快 (5ns)                    │
│  │ L2 Cache│  256KB-1MB, 私有/共享          │
│  └────┬────┘                                │
│       ↓                                     │
│  ┌─────────┐  较慢 (20ns)                   │
│  │ L3 Cache│  8MB-32MB, 共享                │
│  └────┬────┘                                │
│       ↓                                     │
│  ┌─────────┐  最慢 (100ns)                  │
│  │ DDR内存  │  几GB                          │
│  └─────────┘                                │
└─────────────────────────────────────────────┘
```

### Cache 内存 (HWIF_MEM_TYPE_CACHE)

```
CPU 写数据流程：
┌──────┐      ┌─────────┐      ┌─────────┐
│ CPU  │─────→│ Cache   │─────→│ DDR     │
│      │ 快    │ (缓存)   │ 慢   │ (内存)   │
└──────┘      └─────────┘      └─────────┘
              数据暂存这里
              批量写回DDR

特点：
✅ CPU 读写快（命中 Cache）
✅ 适合 CPU 频繁访问的计算场景
❌ 数据可能滞后（Cache 未刷新到 DDR）
❌ 硬件模块（GPU/DSP）可能读到旧数据
```

### Non-Cache 内存 (HWIF_MEM_TYPE_NONCACHE)

```
CPU 写数据流程：
┌──────┐                      ┌─────────┐
│ CPU  │─────────────────────→│ DDR     │
│      │ 直接写入，绕过 Cache  │ (内存)   │
└──────┘                      └─────────┘

特点：
✅ 数据实时同步到 DDR
✅ 硬件模块立即看到最新数据
❌ CPU 读写慢（每次访问 DDR）
❌ 不适合 CPU 密集计算
```

### 运行时确定吗？

**不是运行时确定，而是分配时指定**：

```c
// 分配时就确定了内存类型
HWIF_MEM_ATTRI_ST stAttr;
stAttr.uMemType = HWIF_MEM_TYPE_CACHE;    // 或 HWIF_MEM_TYPE_NONCACHE

// 底层通过页表属性设置
// Cache:    设置页表项的 CACHEABLE 位
// NonCache: 清除页表项的 CACHEABLE 位
```

**页表项设置示例**：

```
页表项 (Page Table Entry)：
┌──────────────────────────────────────┐
│ 物理地址 │ 权限 │ C │ B │ ... │     │
│          │      │ a │ u │     │     │
│          │      │ c │ f │     │     │
│          │      │ h │ f │     │     │
│          │      │ e │ e │     │     │
│          │      │   │ r │     │     │
└──────────────────────────────────────┘
              ↑     ↑
              │     └── Bufferable (写缓冲)
              └──────── Cacheable (可缓存)

Cache 内存:    Cacheable=1, Bufferable=1
NonCache 内存: Cacheable=0, Bufferable=0
```

## 平台物理内存

### 含义

### 为什么需要多个 DDR 区域？

```
场景 1: 视频编码 + 显示同时工作
┌──────────┐     ┌──────────┐
│ 编码器    │     │ 显示引擎  │
│ 需要带宽  │     │ 需要带宽  │
└────┬─────┘     └────┬─────┘
     │                 │
     ↓                 ↓
┌──────────┐     ┌──────────┐
│ DDR ID 2 │     │ DDR ID 1 │   ← 不同内存池，避免竞争
│ 编码内存  │     │ 显示内存  │
└──────────┘     └──────────┘

场景 2: 统一内存池
┌──────────┐     ┌──────────┐
│ 编码器    │     │ 显示引擎  │
└────┬─────┘     └────┬─────┘
     │                 │
     └────────┬────────┘
              ↓
     ┌────────────────┐
     │   DDR ID 0     │   ← 共享内存池，带宽竞争
     │   通用内存      │
     └────────────────┘
```

### 实际使用示例

```c
// 视频编码用内存 - 从编码专用池分配
HWIF_MEM_ATTRI_ST stAttr;
stAttr.uDdrId = 2;                    // 编码专用内存池
stAttr.uUseType = MEM_USE_TYPE_VENC;  // 编码用途
stAttr.uMemType = HWIF_MEM_TYPE_NONCACHE; // 硬件直接访问，不用Cache

// 人脸识别用内存 - 从算法专用池分配
stAttr.uDdrId = 3;                    // 算法专用内存池
stAttr.uUseType = MEM_USE_TYPE_FR;    // 人脸识别用途
stAttr.uMemType = HWIF_MEM_TYPE_CACHE;   // CPU频繁计算，需要Cache
```

## 总结

| 概念                 | 含义             | 确定时机              |
| ------------------ | -------------- | ----------------- |
| **Cache/NonCache** | CPU访问内存时是否经过缓存 | **分配时**通过页表属性固定   |
| **平台物理内存**         | 不同用途的DDR内存分区   | 系统启动时划分，**分配时选择** |
| **DDR ID**         | 内存池编号 (0-3)    | 根据业务需求**分配时指定**   |

**核心理解**：平台物理内存不是物理上独立的 DDR 芯片，而是在同一块 DDR 上**逻辑划分**的不同内存池，用于隔离不同业务的带宽和延迟需求。
