### 第一阶段：编程语言基础（筑基）

安卓开发的核心语言是 Kotlin，但 Java 依然有大量存量代码，两者都需要了解。

1. **Kotlin（首选，必学）**
   * 基础语法：变量、函数、控制流
   * 面向对象：类、对象、继承、接口
   * Kotlin 特色：空安全、扩展函数、Lambda 表达式、高阶函数
   * 协程：异步编程的基础，安卓开发必学
2. **Java（辅助，需懂）**
   * 基础语法及面向对象思想
   * 集合框架、泛型、异常处理
   * **目的**：能看懂老代码、第三方开源库的源码，理解底层机制。

### 第二阶段：安卓核心基础（入门）

掌握安卓应用的基本构成和运行机制。

1. **开发环境搭建**
   * 安装与配置 **Android Studio**
   * 熟悉模拟器的创建与使用
   * 掌握 Gradle 构建工具的基本配置
2. **四大组件（重中之重）**
   * **Activity**：用户界面的载体，深刻理解**生命周期**（onCreate, onResume, onStop 等）。

### 1. MVI是什么？

**MVI (Model-View-Intent)** 是近年来 Android 官方推荐的一种架构模式，它是 MVVM 的进阶版，核心思想是**“单向数据流”**和**“状态集中管理”**。

*   **Model（状态）**：注意，它不是传统的数据层，而是**UI 的唯一状态**。它是一个不可变对象，包含了界面上需要显示的所有信息（如加载中、数据列表、错误信息）。
*   **View（视图）**：界面的渲染器。它不做任何逻辑判断，只做两件事：把用户的操作包装成 Intent 发出去；观察 Model 的变化并重新渲染界面。
*   **Intent（意图）**：这里的 Intent 不是安卓四大组件的那个 Intent，而是**用户的操作意图**（如点击刷新按钮、滑动列表）。

**工作流**：用户操作 -> 产生 Intent -> 传给 ViewModel 处理 -> 生成新的 Model（状态）-> 状态回流给 View -> UI 刷新。

**为什么用 MVI？** 过去 MVVM 中，ViewModel 可能暴露出多个 LiveData（如 `isLoading`、`dataList`、`errorMsg`），UI 需要分别观察它们，容易出现状态不一致（比如数据到了，但 loading 还没消失）。MVI 把所有状态打包成一个整体，要么一起更新，要么不更新，彻底消除了状态不一致的问题。

### 2. 大模型时代更新这么快，看书还有必要吗？

**结论：非常有必要，但看书的目的和方式变了。**

*   **大模型和更新速度解决的是“怎么用”的问题，看书解决的是“为什么”的问题。**
    大模型能瞬间给你一段 Retrofit 的代码，但如果网络请求出了坑（比如 HTTPS 握手失败、缓存策略冲突），你不懂 HTTP 协议的底层，连问 AI 的问题都描述不清楚。
*   **API 会变，但底层原理几十年没变。**
    Android 的 UI 从 XML 变成了 Compose，架构从 MVC 变成了 MVI，但**线程调度、内存管理、操作系统内核、网络协议、数据结构与算法**这些基石没有变。看书（特别是经典书籍）是为了把这些基石打牢。
*   **AI 是“知识的索引”，但你需要“知识的体系”。**
    碎片化地问 AI，得到的是散落的砖块；看书是为了得到一张建筑图纸。有了图纸，你才能用 AI 高效地搬砖。

**建议**：不要看那些“手把手教你写 XX 框架”的速成书（这种直接问 AI 更快），要看就看**《深入理解计算机系统》(CSAPP)、网络协议、Kotlin 编程思想、Android 底层原理**这类沉淀下来的硬核书。

### 3. 音频开发还要学哪些？

音频开发是一个深水区，如果只是“播放/录制本地音频”，Android 自带的 `MediaPlayer` 或 `MediaRecorder` 足矣。但如果想做专业音频（如语音通话、音乐播放器、音视频合成），需要学以下内容：

1.  **基础理论**：
    *   采样率、位深、声道数（理解什么是 PCM 裸数据）。
    *   常见音频格式与编解码（AAC, MP3, Opus, FLAC）。
2.  **Android 原生 API 进阶**：
    *   **AudioTrack / AudioRecord**：直接操作 PCM 裸数据的底层 API，必须掌握。
    *   **Oboe / AAudio**：Google 推出的低延迟音频 API，适合实时语音、乐器类 App。
3.  **跨平台与 C/C++ 底层（核心壁垒）**：
    *   **JNI/NDK 开发**：高性能音频处理必须用 C/C++。
    *   **FFmpeg**：音视频界的瑞士军刀，解码、编码、格式转换必学。
    *   **OpenSL ES**：Android 底层的 C 语言音频接口。
4.  **音频处理算法（视方向而定）**：
    *   如果做语音通话：回声消除（AEC）、噪声抑制（ANS）、自动增益（AGC）。
    *   如果做音乐/特效：混响、均衡器（EQ）、变声（基于 WebRTC 或 SoundTouch 库）。

### 4. 网络和存储都是现有的工具和 API 吗？

**是的，绝大多数情况下，你都是在“调包”和“调 API”，不需要自己造轮子，但你需要懂这些轮子的适用场景。**

*   **网络请求**：
    *   底层 API：Java 的 `HttpURLConnection`、OkHttp 的底层 Socket（没人直接用这些写业务）。
    *   **行业标准工具**：**OkHttp**（负责底层连接与拦截） + **Retrofit**（负责接口声明与数据解析）。你只需要定义一个接口，写几行注解，网络请求就完成了。
*   **数据存储**：
    *   轻量键值对：`SharedPreferences`（老） -> 官方推荐升级为 **DataStore**（新，基于协程）。
    *   结构化数据库：原生 `SQLite`（写 SQL 太痛苦） -> **Room**（Google 官方 ORM 库，用注解帮你自动生成增删改查代码）。
    *   文件存储：Android 提供了 `Context.getFileDir()` 等一系列 API，加上 `MediaStore` 处理多媒体文件。

**重点**：工具封装了复杂性，但**没有消除复杂性**。如果网络请求需要加签、缓存、多路复用，或者数据库遇到死锁、迁移失败，你就必须翻看这些库的源码或懂其底层原理了。

### 5. 四大组件是什么，是几个封好的库吗？

**不是库，而是 Android 操作系统层面的“四大基石概念”。** 它们是 Android 系统架构的核心设计，所有的 App 都是基于这四个组件拼装出来的。

1.  **Activity（活动）**：
    *   **是什么**：App 的一个页面。你看到的每一个界面，背后都是一个 Activity。
    *   **作用**：绘制 UI，接收用户触摸/按键事件。
2.  **Service（服务）**：
    *   **是什么**：后台干活的组件。
    *   **作用**：即使 App 的界面关了，Service 依然可以在后台运行（比如音乐播放器切到后台继续放歌，或者后台默默上传日志）。
3.  **BroadcastReceiver（广播接收器）**：
    *   **是什么**：全局的监听器。
    *   **作用**：接收系统或其他 App 发出的通知。比如监听开机启动、监听网络状态变化、监听电量低等。
4.  **ContentProvider（内容提供者）**：
    *   **是什么**：跨 App 的数据共享通道。
    *   **作用**：如果你想读取手机通讯录、相册，或者让你的数据给别的 App 用，就必须通过 ContentProvider 提供接口。

**为什么强调它们是“组件”而不是“库”？**
因为**它们的生命周期是由 Android 系统（系统服务 ActivityManagerService）控制的，而不是你的代码控制的**。你只能重写它们的方法（如 `onCreate`），在合适的时机做合适的事，而不能自己去 `new` 一个 Activity 并让它显示。这是初学者从普通 Java/Kotlin 编程转向 Android 编程时，思维转变最大的一点。
