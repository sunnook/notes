## 1. **自旋锁 (Spinlock)**

自旋锁是一种忙等待的锁，线程在获取锁时会循环检查锁的状态，而不是立即阻塞。

### C 语言实现示例：
```c
#include <stdatomic.h>

typedef atomic_flag spinlock_t;

// 初始化自旋锁
#define SPINLOCK_INIT ATOMIC_FLAG_INIT

// 加锁
void spinlock_lock(spinlock_t *lock) {
    while (atomic_flag_test_and_set(lock)) {
        // 自旋等待，可以加入 CPU 暂停指令优化性能
        #ifdef __x86_64__
        asm volatile("pause" ::: "memory");
        #endif
    }
}

// 解锁
void spinlock_unlock(spinlock_t *lock) {
    atomic_flag_clear(lock);
}

// 使用示例
spinlock_t lock = SPINLOCK_INIT;

void critical_section() {
    spinlock_lock(&lock);
    // 临界区代码
    spinlock_unlock(&lock);
}
```

## 1. `pthread_mutex_lock` vs 自旋锁 vs 信号量

**关键区别：线程状态**

- **`pthread_mutex_lock`（互斥锁）**：
  - 当锁被占用时，线程会**进入阻塞状态**（睡眠）
  - 内核会将线程从运行队列移除，调度其他线程
  - 解锁时，内核唤醒等待线程
  - **适用场景**：临界区执行时间较长（>上下文切换开销）

- **自旋锁**：
  - 当锁被占用时，线程在**用户空间循环检查**（忙等待）
  - 线程保持运行状态，持续消耗CPU
  - **适用场景**：临界区很短（<上下文切换开销），多核CPU

- **信号量**：
  - 基于内核的等待队列，线程会阻塞
  - 比互斥锁更重量级，支持计数信号量

**你说的"信号量也是这样实现"**：信号量底层确实有等待机制，但它是**内核级阻塞**，而自旋锁是**用户级忙等待**。

```c

asm volatile("pause" ::: "memory");
#endif
```

- **推荐加上**，但不是必须

  - 避免内存顺序冲突
  - 提升超线程性能
- 如果没有`pause`，CPU会以最高速度循环，浪费更多资源
