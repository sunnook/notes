### 一、 源码的“分层”架构（自上而下）

Android 的设计哲学是严格的分层隔离，下层永远不知道上层是什么，上层只能通过特定接口调用下层。你可以把它想象成一个汉堡：

1.  **Application 层（应用层）**
    *   **对应目录：** `packages/apps/`
    *   **内容：** 系统自带的应用（如 Settings, Launcher, SystemUI, 电话拨号器等）。对于海康的定制系统，这里可能放着你公司的定制 APK，或者直接把 APK 预置在这里。
2.  **Application Framework 层（应用框架层 / Java 层）**
    *   **对应目录：** `frameworks/base/`、`frameworks/av/`
    *   **内容：** 开发者平时用的 `Activity`、`Service`、`CameraManager` 都在这里。它是用 Java/Kotlin 写的，是 App 和底层系统服务沟通的“桥梁”。
3.  **System Services & Libraries 层（系统服务与原生库层 / C/C++ 层）**
    *   **对应目录：** `frameworks/native/`、`system/`、`libcore/`、`external/`
    *   **内容：** 真正干重活的地方。包含了 `system_server`（管理四大组件）、`SurfaceFlinger`（合成画面）、`AudioFlinger`（混音）。`external/` 下则是海量的开源第三方库（如 `ffmpeg`, `libvpx`, `openssl`）。
4.  **Hardware Abstraction Layer (HAL 层 / 硬件抽象层)**
    *   **对应目录：** `hardware/`、`device/rockchip/`
    *   **内容：** 这是 Android 区别于普通 Linux 的核心。为了兼容不同硬件，Google 规定了一套标准接口。芯片厂商（如 Rockchip）在这里实现具体的摄像头驱动、音频驱动。**这是嵌入式开发最常改动的地方。**
5.  **Linux Kernel 层（内核层）**
    *   **对应目录：** `kernel/` (通常只包含配置和预编译模块，完整内核源码在另一个独立仓库)
    *   **内容：** 真正控制硬件的驱动程序。

### 二、 源码的“分模块”拆解（结合你的目录树）

按照功能，我们可以把目录树里的文件夹归类：

#### 1. 核心运行与构建模块
*   **`art/`**：Android Runtime，执行 Java/Kotlin 代码的虚拟机（你之前问的）。
*   **`bionic/`**：Android 专属的 C/C++ 标准库。因为嵌入式设备资源有限，Android 没用 glibc，而是自己写了更轻量的 bionic（包含 `libc`, `libm`, `libdl`）。
*   **`build/`**：Android 的编译系统。早期是 Make，现在全面转向 **Soong**（`Android.bp` 文件）和 **Bazel**（`BUILD` 和 `WORKSPACE` 文件）。
*   **`prebuilts/`**：预编译好的工具链（如 JDK, Clang, GCC）。因为 Android 源码太大，不可能全部源码编译，所以编译器等工具直接放二进制。

#### 2. 框架与服务模块
*   **`frameworks/base/`**：Android Java 框架核心。包含了四大组件的实现、UI 系统（View 的底层）、各种 Manager（`WindowManager`, `PackageManager`）的 Java 端代码。
*   **`frameworks/av/`**：**音视频核心！**（你做音视频必须关注的）。包含了 `MediaCodec`、`CameraService`、`AudioFlinger` 的 C++ 实现。
*   **`frameworks/native/`**：C/C++ 框架核心。包含 `SurfaceFlinger`（显示合成）、Binder IPC 通信底层。

#### 3. 硬件与定制模块（嵌入式重点）
*   **`device/rockchip/`**：Rockchip 平台的板级配置。里面有关键的 `BoardConfig.mk`，定义了分区大小、CPU 架构、硬件参数。
*   **`hardware/rockchip/`**：Rockchip 的 HAL 层实现。比如他们怎么实现摄像头、音频、图形渲染的 HAL。
*   **`vendor/hikvision/`**：海康威视的私有定制代码。可能包含海康自研的库、特定的系统服务、安全模块等。

#### 4. 外部依赖库
*   **`external/`**：几百个第三方开源项目。比如编解码用的 `libavc`（H.264软解）、`libvpx`（VP8/9）、`libopus`（音频编码）、`sqlite`（数据库）。Android 就像一个巨大的开源软件缝合怪。

### 三、 入口在哪里？如何理解？

面对几百万行代码，**千万不要像看小说一样从第一个文件开始看**。Android 有两个维度的“入口”：

#### 1. 编译的入口（如何把源码变成镜像）
*   **入口文件：** 根目录的 `Makefile`（被 `build/core/main.mk` 引入）或 `build/bazel/BUILD`。
*   **如何理解：** 你执行 `source build/envsetup.sh` -> `lunch` -> `make` 时，编译系统会读取 `device/rockchip/xxx/BoardConfig.mk` 和 `vendor/hikvision/xxx/device.mk`，根据这些配置把 `frameworks`、`packages`、`external` 里的代码分别编译成 `.jar`、`.so`、`.apk`，最后打包成 `system.img`、`boot.img` 等镜像文件。

#### 2. 运行的入口（开机后系统怎么跑起来）
*   **启动链入口：**
    1.  **Bootloader (不在源码树中)**：初始化硬件，加载内核。
    2.  **`kernel/`**：启动 Linux 内核，挂载根文件系统，最后拉起第一个用户空间进程 `init`。
    3.  **`system/core/init/`**：**这是 Android 源码真正的运行时起点！** 解析 `init.rc` 脚本，启动关键的守护进程。
    4.  **`frameworks/base/cmds/app_process.cpp` (Zygote)**：`init` 启动 Zygote。Zygote 预加载了整个 Android Framework 和 ART 虚拟机。
    5.  **`frameworks/base/services/java/com/android/server/SystemServer.java`**：Zygote fork 出 `system_server`，在这里面启动了 AMS、WMS 等几百个系统服务。系统服务就绪后，发送消息给 Zygote，启动 Launcher（桌面）。

### 四、 给你的源码阅读建议（针对音视频/嵌入式开发）
