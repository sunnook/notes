### 一、分层架构（自顶向下）

| 层 | 说明 |
|---|------|
| **应用层** | 系统应用 + 第三方 App |
| **Framework 层** | Java API 框架，提供 Activity、Service、ContentProvider 等组件 |
| **Native 层** | C/C++ 库 + Android Runtime (ART) |
| **HAL 层** | 硬件抽象层，解耦 Framework 与硬件驱动 |
| **Linux 内核层** | 驱动、内存管理、进程调度、Binder 等 |

---

### 二、Framework 层核心模块

| 模块 | 职能 |
|------|------|
| **AMS** | Activity 生命周期管理、任务栈调度 |
| **WMS** | 窗口管理、Surface 分配、触控事件分发 |
| **PMS** | APK 安装、权限管理、包信息查询 |
| **IMS** | 输入事件采集与分发 |
| **NMS** | 通知栏管理 |
| **ContentProvider** | 跨进程数据共享 |
| **View System** | UI 控件体系 |
| **Resource Manager** | 资源加载与适配 |

---

### 三、一句话总结

> **分层解耦，模块各司其职**——Framework 向上提供统一 API，向下通过 JNI 衔接 Native 层，最终经 HAL 调用内核驱动，实现“应用不感知硬件”的设计目标。

## 音视频场景下的分层与模块功能

### 一、总览：一次视频播放的跨层调用

```
用户点击播放按钮
  → MediaPlayer.start()
    → JNI 调用 Native MediaPlayer
      → MediaPlayerService（System Server 进程）
        → NuPlayer / Stagefright
          → MediaCodec（编解码）
            → OMX / Codec2 HAL
              → 硬件编解码器驱动
```

---

### 二、各层具体职责

| 层 | 音视频相关模块 | 作用 |
|---|--------------|------|
| **应用层** | `MediaPlayer` / `ExoPlayer` / `MediaRecorder` | 播放、录制、停止、seek 等 API |
| **Framework (Java)** | `android.media.*` 包 | 封装播放器、编解码器、音轨管理，暴露给 App |
| **JNI** | `android_media_MediaPlayer.cpp` | 桥接 Java 层与 Native 层 |
| **Native Framework** | `MediaPlayerService` / `Stagefright` / `NuPlayer` | 解析容器格式、管理播放状态、音视频同步 |
| **HAL** | `OMX HAL` / `Codec2 HAL` / `Audio HAL` | 抽象硬件编解码器和音频设备 |
| **内核** | `V4L2` / `ALSA` / `ION` / `DMA-BUF` | 驱动摄像头、音频设备、内存管理 |

---

### 三、核心模块功能拆解

#### 1. 播放链路

| 模块 | 功能 |
|------|------|
| **MediaPlayer** | 提供播放控制 API（start/pause/seek） |
| **MediaPlayerService** | 跨进程服务，管理多个播放器实例 |
| **NuPlayer** | 解析 MP4/MKV 等容器，分离音视频轨 |
| **MediaCodec** | 调用硬件编解码器，解码 H.264/H.265 |
| **AudioTrack** | 将 PCM 数据送入音频 HAL 播放 |
| **Surface / ANativeWindow** | 将解码后的视频帧渲染到 Surface |

#### 2. 录制链路

| 模块 | 功能 |
|------|------|
| **MediaRecorder** | 提供录制控制 API |
| **Camera / Camera2** | 采集视频帧 |
| **AudioRecord** | 采集音频 PCM |
| **MediaCodec（编码模式）** | 将原始帧编码为 H.264/H.265 |
| **MediaMuxer** | 将音视频轨封装为 MP4 容器 |

#### 3. 编解码

| 模块 | 功能 |
|------|------|
| **MediaCodec** | 编解码统一接口，支持同步/异步模式 |
| **OMX HAL / Codec2 HAL** | 对接硬件编解码器（GPU、VPU、DSP） |
| **Stagefright** | 原生框架，管理编解码器选择与生命周期 |

#### 4. 渲染显示

| 模块 | 功能 |
|------|------|
| **SurfaceFlinger** | 合成各 Surface 图层 |
| **HwComposer HAL** | 硬件合成，减少 GPU 负载 |
| **DRM/KMS** | 内核显示驱动，控制显示输出 |

### 1. HAL 是内核设备的抽象

**是的，这个理解完全正确，但可以更精确。**

HAL 的本质是对**硬件功能**的抽象，而非直接对内核驱动文件的抽象。

| 对比 | 内核驱动 | HAL |
|------|---------|-----|
| **操作对象** | 寄存器、中断、DMA | 功能接口（如“解码一帧”） |
| **接口形式** | `ioctl`、`read`、`write` | C++ 头文件定义的虚函数 |
| **运行态** | 内核空间 | 用户空间 |
| **举例** | V4L2 驱动：`VIDIOC_S_FMT` | Camera HAL：`process_capture_request()` |

**关键区别：**
- 内核驱动暴露的是**机制**（如何传输数据）
- HAL 封装的是**策略**（何时、以何参数调用驱动）

**一句话：** HAL 把“操作 `/dev/video0` 的 ioctl 序列”封装成“启动预览”一个函数，让上层不必关心底层设备节点的操作细节。

### 2. Native 层是解析软硬件格式吗？是 Decoder 的角色吗？

**Native 层不只是 Decoder，它是一个“中间层引擎”，负责调度和编排，而非直接解析。**

#### Native 层的三个角色

| 角色 | 模块 | 具体功能 |
|------|------|---------|
| **解析器（Parser）** | `Extractor`（如 `MP4Extractor`） | 解析容器格式，分离音视频轨 |
| **调度器（Orchestrator）** | `NuPlayer`、`Stagefright` | 管理播放状态机，协调各组件 |
| **编解码客户端** | `MediaCodec`（Native 部分） | 调用 HAL 接口，下发编解码任务 |

#### 关键：Native 层不直接解码

```
Native 层 MediaCodec
  → 调用 OMX HAL 的 emptyBuffer / fillBuffer
    → HAL 内部调用硬件编解码器驱动
      → 硬件 VPU/DSP 执行解码
```

**Native 层是“指挥者”，不是“执行者”：**
- 它知道何时需要解码、解码参数是什么
- 但真正的解码运算由 HAL 层调用硬件完成
- 如果硬件不支持，Native 层会 fallback 到**软解码器（软件实现）**，此时软解码器也在 Native 层运行，但不经过 HAL

**一句话：** Native 层是“调度中心 + 软解码后备”，硬解码通过 HAL 下发到硬件，软解码在 Native 层用 CPU 完成。

### 3. Framework 层向上提供哪些功能？

Framework 层向上（应用层）提供三大类能力：

#### 一、接口抽象与封装

| 模块 | 提供的 API | 屏蔽的复杂性 |
|------|-----------|-------------|
| `MediaPlayer` | `start()`、`pause()`、`seekTo()` | 播放器状态机、音视频同步、缓冲区管理 |
| `MediaRecorder` | `start()`、`stop()`、`setVideoSource()` | 编码器初始化、容器封装、音视频交织 |
| `MediaCodec` | `configure()`、`queueInputBuffer()`、`dequeueOutputBuffer()` | Codec 选择、HAL 调用、异步回调 |
| `AudioTrack` | `write()`、`play()`、`pause()` | 音频 HAL 交互、缓冲区管理、采样率转换 |

#### 二、资源管理与生命周期

| 能力 | 说明 |
|------|------|
| **多路复用** | 多个 App 同时使用麦克风、摄像头时的策略管理 |
| **优先级调度** | 通话 > 闹钟 > 媒体播放，自动 ducking |
| **电源管理** | 播放时持有 WakeLock，防止 CPU 休眠 |
| **权限控制** | `RECORD_AUDIO`、`CAMERA` 权限检查 |

#### 三、跨进程服务

| 机制 | 说明 |
|------|------|
| **Binder IPC** | App 进程 → MediaServer 进程，透明调用 |
| **回调机制** | `onCompletionListener`、`onErrorListener` 等异步通知 |
| **Surface 传递** | App 创建 Surface，跨进程传给 MediaServer 渲染 |

### 四、一张图总结三层分工

```
┌────────────────────────────────────────────┐
│  Framework 层（Java）                       │
│  “提供什么功能”：播放/录制/编解码 API        │
│  “屏蔽什么”：跨进程、状态管理、权限          │
└──────────────┬─────────────────────────────┘
               │ JNI
┌──────────────▼─────────────────────────────┐
│  Native 层（C++）                           │
│  “做什么”：解析容器、调度编解码、同步音视频   │
│  “不做什么”：不直接操作硬件寄存器            │
└──────────────┬─────────────────────────────┘
               │ HAL 接口
┌──────────────▼─────────────────────────────┐
│  HAL 层（C++ 用户态库）                      │
│  “做什么”：封装内核驱动调用序列              │
│  “抽象什么”：硬件的功能，而非设备节点         │
└──────────────┬─────────────────────────────┘
               │ ioctl / read / write
┌──────────────▼─────────────────────────────┐
│  内核驱动（C，内核空间）                      │
│  “做什么”：操作寄存器、DMA 传输、中断处理     │
└────────────────────────────────────────────┘
```

**一句话总结：** Framework 管“用什么”，Native 管“怎么调度”，HAL 管“怎么操作硬件”，内核管“执行”。
