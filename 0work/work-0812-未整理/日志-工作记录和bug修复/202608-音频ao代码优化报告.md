# 音频输出(AO)数据处理模块重构优化汇报

## 一、 优化背景与目标
本次重构针对 `priv_ao_data_process` 音频输出核心处理函数。原版本主要针对单声道场景设计，随着业务需求升级，需支持立体声（双声道）处理、混音防回环、以及更精细的算法与调试能力。
本次优化旨在**提升多声道处理能力、增强系统健壮性、规范化音频数据流转**，同时修复潜在的逻辑漏洞。

## 二、 核心优化项详解

### 1. 架构级升级：全面支持多声道与格式转换
*   **引入平面/交织格式转换机制**：
    *   **获取数据后**：若检测到立体声数据，调用 `priv_ao_copy_inter2plan` 将交织格式转为平面格式。这符合底层音频算法（如重采样、音量控制）通常按通道独立处理的规范。
    *   **送播前**：处理完成后，调用 `priv_ao_copy_plan2inter` 将平面格式转回交织格式，满足硬件层 `hwif_ao_send_frame` 的输入要求。
*   **单声道自适应补齐**：送播前若发现当前仅为单声道数据，会自动将其复制到另一声道（`uSoundMode` 修改为 `STEREO`），保证硬件始终接收到完整的双声道数据，避免底层驱动异常。

### 2. 算法处理重构：按声道独立管理重采样
*   **多通道独立句柄管理**：将原有的单一重采样句柄 `stAlgChnInfo` 升级为数组 `stAlgChnInfo[uSoundIdx]`，为每个声道创建独立的重采样实例。
*   **状态机分离**：将重采样句柄的“销毁”与“重建”逻辑拆分为两个独立的循环。先遍历销毁所有采样率不匹配的旧句柄，再遍历创建新句柄。避免了在重建过程中出现状态不一致的问题。
*   **参数精准传递**：重采样输入输出缓冲区指针严格按声道偏移（`pInBuf + uFrameLen * uSoundIdx`）进行隔离，确保多声道算法处理互不干扰。

### 3. 逻辑修复与健壮性提升
*   **混音防回环机制**：在向 Amer（混音器）发送数据前，增加了 `uPlayChn != AO_AMER_DEV_ID` 的判断。**修复了混音通道数据再次送入混音器导致递归回声/死循环的严重隐患**。
*   **位宽强校验**：新增了获取数据后的位宽校验（`uBitWidth`），若与设备配置不一致则直接返回错误，防止因数据格式不匹配导致的底层内存越界或杂音。
*   **参数传递规范化**：`priv_ao_get_frame` 新增 `stReqBaseAttr` 参数，将设备基础属性（采样率、位宽等）主动传递给前置模块，指导其输出符合预期的数据。
*   **音量控制接口升级**：`priv_ao_vol_control` 新增 `uProcSudMode` 参数，使音量算法感知声道数，支持多声道独立或协同控制。

### 4. 调试与 DFX (Design for X) 能力增强
*   **分声道文件保存**：DFX 抓帧保存逻辑（重采样前、重采样后、最终输出）全面支持按声道独立保存（文件名包含 `sound%d`），极大提升了多声道问题的定位效率。
*   **测试模式解耦**：
    *   测试模式处理逻辑中引入了独立的 `stAoTestFrameBuf`，避免直接污染最终送播的帧数据。
    *   标准音源替换逻辑支持多声道循环填充。

### 5. 代码结构与可读性优化
*   **循环结构优化**：将送播逻辑的 `do-while` 循环重构为更清晰的 `for` 循环（`for(uSendLen = 0; uSendLen < uOriLen; uSendLen += uFrmLenSend)`），边界条件更明确，降低了死循环风险。
*   **指针别名规范化**：引入 `pstAoDevBaseAttr`、`pstAudResFrame` 等局部指针别名，减少了冗长结构体指针的反复解引用，提升代码整洁度。
*   **常量安全性**：使用 `const` 修饰只读指针（如 `const AUD_BASE_ATTR_ST* pstAoDevBaseAttr`），防止意外修改，增强编译期检查。

## 三、 优化前后对比总结

| 维度 | 优化前 | 优化后 |
| :--- | :--- | :--- |
| **声道支持** | 仅支持单声道，或底层隐式处理 | 显式支持双声道，自动处理单双声道转换及平面/交织转换 |
| **重采样管理** | 单一全局句柄，销毁与创建耦合 | 按声道独立管理句柄数组，销毁与创建逻辑分离，状态更稳定 |
| **混音安全性** | 无通道来源校验，存在回环风险 | 增加混音通道过滤判断，杜绝回声回环 |
| **参数校验** | 仅校验采样率 | 增加位宽强校验，前置模块参数主动下发 |
| **DFX 调试** | 单一文件保存，无法区分声道 | 按声道独立保存 PCM，定位更精准 |
| **代码结构** | `do-while` 循环边界易错，指针解引用冗长 | `for` 循环边界清晰，引入局部指针别名，可读性大幅提升 |

## 四、 总结
本次重构在保证原有单声道业务正常流转的前提下，平滑接入了对立体声的全链路支持。不仅修复了混音回环等高危隐患，还通过格式转换解耦、算法句柄分离等手段，显著提升了底层音频模块的可扩展性与稳定性，为后续复杂音频场景（如空间音频、多声道混音）奠定了坚实的代码基础。
