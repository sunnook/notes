## 一、Spring Boot 和 Spring Cloud 是什么？

### Spring Boot
可以理解为**快速搭建单个应用后台的脚手架**。就像你装修房子时，不用自己从零开始砌墙、拉电线，而是用现成的精装方案，直接拎包入住。

- **传统 Spring 开发**：需要大量 XML 配置，像手工打造每件家具
- **Spring Boot**：自动配置、内嵌服务器（Tomcat），开箱即用，像买宜家成品家具

**打个比方**：你要开一家奶茶店（一个App后台）：
- Spring Boot = 给你一个装修好的店面，设备齐全，你直接做奶茶卖就行
- 不需要关心水电怎么接（服务器配置）、收银机怎么装（数据库连接）

### Spring Cloud
是**管理多个Spring Boot服务的工具集**。当你开了100家奶茶连锁店，需要统一管理时用。

- 服务发现：知道每家店在哪里（Eureka/Nacos）
- 配置中心：统一改配方（Spring Cloud Config）
- 负载均衡：客人分流到不忙的店（Ribbon）

**核心区别**：
| | Spring Boot | Spring Cloud |
|---|---|---|
| 作用 | 开发**单个**后台服务 | 管理**多个**后台服务协同 |
| 类比 | 一家奶茶店 | 连锁店管理系统 |
| 能否独立使用 | ✅ 可以 | ❌ 必须基于Spring Boot |

### 微信小程序
- 是**前端应用**，运行在微信里

### 三、核心难点深入：手机本地到底要处理什么？

#### 1. 视频预览（低延迟是关键）

**流程**：
```
摄像头 → (RTSP) → ZLMediaKit服务器 → (WebRTC/RTMP) → 安卓App
                                                      ↓
                                            MediaCodec硬解码 → SurfaceView显示
```

**手机端要做的事**：
- **拉流**：用ljkplayer、ExoPlayer或自研播放器接收流
- **解码**：必须用**MediaCodec硬解**（软解会发烫、耗电）
- **缓冲策略**：为了低延迟，缓冲区要设得很小（100ms以内），但网络不好会卡顿，需要做丢包补偿

#### 2. 美颜（实时视频处理）

**美颜是在手机本地做的，服务器不参与！**

**原理**：
```
解码后的视频帧（YUV格式）
        ↓
转成OpenGL纹理（Texture）
        ↓
GPU Shader处理：
  - 磨皮：双边滤波/高通滤波
  - 瘦脸：网格变形（Liquefy）
  - 大眼：局部缩放
        ↓
渲染到屏幕（或重新编码推流）
```

**技术栈**：
- 安卓：OpenGL ES 2.0/3.0
- 常用库：GPUImage（已停更）、自行编写Shader
- 性能关键：必须在GPU上做，不能回读CPU，否则卡死

#### 3. 对讲（双向音频）

**流程**：
```
手机A说话：
  麦克风采集PCM → AAC编码 → WebSocket发送 → 服务器 → 转发给摄像头

摄像头声音：
  摄像头音频流 → 服务器 → WebSocket/WebRTC → 手机A解码播放
```

**手机端要做的事**：
- **回声消除**（AEC）：如果不做，对方会听到自己声音的回声
- **噪声抑制**（ANS）：降低环境噪音
- **自动增益**（AGC）：说话声音忽大忽小自动调整
- 这些可以用**WebRTC的AudioProcessing模块**，或安卓自带的`AcousticEchoCanceler`

#### 4. 录像回放（拖动、倍速）

**手机端要做的事**：
- **Seek（拖动进度条）**：需要服务器支持Range请求，手机端根据拖动位置重新请求对应时间点的视频片段
- **倍速播放**：安卓端改变解码/渲染速率
  - 1x：正常解码渲染
  - 2x：要么每两帧丢一帧，要么`MediaCodec`设置更高输出帧率
  - 音频倍速：用`Sonic`库或`SoundTouch`做变速不变调

## 问题3：可以支持多设备视频通话吗？可以用WHEP/WHIP协议吗？

**答案：可以，而且WHEP/WHIP正是为此而生的！**

### WHEP/WHIP是什么？

这是WebRTC生态的两个标准协议（IETF标准）：

```
WHEP (WebRTC HTTP Egress Protocol)
  → 用于"拉流"（观看）
  → 手机看摄像头画面，就是WHEP

WHIP (WebRTC HTTP Ingest Protocol)  
  → 用于"推流"（发布）
  → 手机把自己的画面推到服务器，就是WHIP
```

**传统WebRTC的问题**：需要复杂的信令交换（SDP Offer/Answer），需要WebSocket或SIP。

**WHEP/WHIP的优势**：用简单的HTTP POST就能建立WebRTC连接，信令极简。

### 多设备视频通话架构

```
              ┌─────────────────────┐
              │   ZLMediaKit        │
              │   (支持WHEP/WHIP)   │
              └──┬──────┬──────┬────┘
                 │      │      │
        WHIP推流 │      │      │ WHIP推流
                 ↓      ↓      ↓
            ┌────┐  ┌────┐  ┌────┐
            │手机A│  │手机B│  │手机C│
            │     │  │     │  │     │
            │WHEP拉│  │WHEP拉│  │WHEP拉│
            │B和C │  │A和C │  │A和B │
            └────┘  └────┘  └────┘
```

```kotlin
// 使用WHIP协议推流到服务器
class WhipPublisher {
    fun publish(localStream: MediaStream) {
        // 1. 创建PeerConnection
        val pc = PeerConnectionFactory.createPeerConnection()
        
        // 2. 添加本地流（摄像头采集+美颜处理后的画面）
        pc.addStream(localStream)
        
        // 3. 生成SDP Offer
        val offer = pc.createOffer()
        pc.setLocalDescription(offer)
        
        // 4. 通过HTTP POST发送Offer（这就是WHIP！）
        val response = httpClient.post("http://server:8080/whip/room123") {
            body = offer.sdp
            contentType = "application/sdp"
        }
        
        // 5. 获取Answer，设置远端SDP
        pc.setRemoteDescription(response.body)
        
        // 连接建立，开始推流！
    }
}
```

**安卓端WHEP拉流（观看其他手机的画面）**：
```kotlin
// 使用WHEP协议拉流
class WhepPlayer {
    fun play(remoteStreamId: String, surface: Surface) {
        // 1. 创建PeerConnection
        val pc = PeerConnectionFactory.createPeerConnection()
        
        // 2. 通过HTTP POST获取远端SDP（这就是WHEP！）
        val response = httpClient.post("http://server:8080/whep/$remoteStreamId") {
            contentType = "application/sdp"
        }
        
        // 3. 设置远端SDP，生成Answer
        pc.setRemoteDescription(response.body)
        val answer = pc.createAnswer()
        pc.setLocalDescription(answer)
        
        // 4. 渲染远端视频到Surface
        pc.onAddStream { stream ->
            stream.videoTracks[0].addSink(surface)
        }
    }
}
```

## 一、Janus vs SRS vs ZLMediaKit：谁支持RTSP + WHEP/WHIP？

### 核心对比

| 功能 | **Janus** | **SRS** | **ZLMediaKit** |
|---|---|---|---|
| **RTSP支持** | ❌ 不原生支持，需插件 | ❌ 不原生支持，需转协议 | ✅ **原生支持** |
| **WHEP/WHIP** | ✅ 原生支持（通过HTTP） | ✅ 5.0+原生支持 | ✅ **原生支持** |
| **WebRTC** | ✅ 核心功能，极强 | ✅ 5.0+支持 | ✅ 支持 |
| **GB28181** | ❌ 不支持 | ❌ 不支持 | ✅ **原生支持** |
| **RTMP** | ❌ 不原生支持 | ✅ **原生支持** | ✅ 支持 |
| **架构** | C语言，插件化 | C++，单进程 | C++，高性能 |
| **适合场景** | WebRTC会议、SFU | 直播、CDN | **安防、国标、多协议融合** |

### 结论：**ZLMediaKit 最适合你的场景**

**理由**：
1. **RTSP原生支持**：海康摄像头推流就是RTSP，ZLMediaKit直接接入，不用转协议
2. **WHEP/WHIP原生支持**：手机端用WebRTC拉流/推流，延迟<200ms
3. **GB28181支持**：如果以后接公安平台或国标设备，直接支持
4. **多协议转换**：摄像头RTSP进来 → 自动转WebRTC/WHEP给手机，一条龙

**Janus的问题**：不直接支持RTSP，需要额外搭一个RTSP→WebRTC的转换服务（比如用FFmpeg转），架构复杂。

**SRS的问题**：RTSP支持弱，主要面向直播推流场景，不适合安防的多协议融合。

```kotlin
class MultiPartyCallManager {
    // 每个参会者对应一个远程视频Surface
    private val remoteViews = List(4) { RemoteVideoView() }
    
    // WHIP推流：把自己的画面推到房间
    private val whipPublisher: WhipPublisher
    
    // WHEP拉流：拉取其他4个人的画面
    private val whepPlayers = List(4) { WhepPlayer() }
    
    fun joinMeeting(roomId: String) {
        // 1. 加入房间
        signalingService.joinRoom(roomId)
        
        // 2. 开启本地采集（摄像头+美颜）
        val localStream = createLocalStreamWithBeauty()
        
        // 3. WHIP推自己的流
        whipPublisher.publish("room/$roomId/myStream", localStream)
        
        // 4. 监听新参与者加入
        signalingService.onParticipantJoined { participantId ->
            // 5. WHEP拉对方的流
            val player = whepPlayers[participantIndex]
            player.play(
                url = "whep://server/room/$roomId/$participantId",
                surface = remoteViews[participantIndex].surface
            )
        }
    }
    
    private fun createLocalStreamWithBeauty(): MediaStream {
        // 摄像头采集
        val cameraStream = cameraCapturer.startCapture()
        
        // 美颜处理（OpenGL ES）
        val beautyFilter = BeautyFilter()
        beautyFilter.setStrength(0.8f)
        
        return beautyFilter.process(cameraStream)
    }
}
```

// Spring Boot 信令服务
@RestController
class MeetingController {
    
    @PostMapping("/meetings/create")
    fun createMeeting(@RequestBody request: CreateMeetingRequest): Meeting {
        // 1. 在ZLMediaKit创建房间
        zlmClient.createRoom(request.roomId)
        
        // 2. 记录到数据库
        val meeting = Meeting(
            roomId = request.roomId,
            creatorId = request.userId,
            participants = mutableListOf(request.userId)
        )
        meetingRepository.save(meeting)
        
        // 3. 通知其他人（如果有邀请）
        request.inviteeIds.forEach { userId ->
            wsHandler.sendInvitation(userId, meeting)
        }
        
        return meeting
    }
    
    @PostMapping("/meetings/{roomId}/join")
    fun joinMeeting(@PathVariable roomId: String, @RequestParam userId: String) {
        // 1. 加入ZLMediaKit房间
        zlmClient.joinRoom(roomId, userId)
        
        // 2. 通知房间内其他人
        wsHandler.broadcast(roomId, "participant_joined", userId)
    }
}
