# 极简双硬盘双系统安装指南（最终完美版）



## 前置关键说明（核心架构）

EFI分区**必须共用原来512G Windows固态上自带的500MB FAT32 EFI分区**，不要在1T新固态新建EFI；装好后开机自动弹出Windows/Ubuntu双系统选择菜单（GRUB接管引导）。



---



## 步骤1：Windows提前设置（安装前必做）

1. **关闭「快速启动」**：在控制面板的“电源选项”中关闭，否则Linux无法读写NTFS共享盘。

2. **SATA RAID 转 AHCI（强烈建议）**：不转的话Ubuntu安装界面大概率**找不到新硬盘**。

&#x20;  - *无损切换法（防蓝屏）*：Win+R输入`msconfig` -> 引导 -> 勾选“安全引导” -> 重启进BIOS将SATA改为AHCI -> 进Windows安全模式 -> 再次`msconfig`取消“安全引导” -> 重启即可。

3. **新盘保持原样**：1T佰维新固态**全程保持整块未分配**，千万不要在Windows磁盘管理里初始化或格式化。



## 步骤2：下载镜像 + 制作U盘启动盘

1. 官网下载 **Ubuntu Desktop 桌面版 ISO**（不要下服务器版）。

2. 准备8G以上空U盘，用 Rufus 或 Etcher 把镜像写入U盘（U盘数据会清空）。



## 步骤3：U盘启动进入安装界面

1. 插U盘，重启电脑狂按 F12（或对应快捷键），选 **UEFI开头** 的U盘启动项。

2. 进入安装向导，语言、网络、第三方软件按需勾选。

3. 安装类型选择：**其他选项（Something else）**（进入手动分区核心界面）。



## 步骤4：1T新固态手动分区（核心操作）

选中空白1T未分配空间，点击“+”号分3个区：

1. **共享NTFS分区**：200G（用于两边互传文件，格式选NTFS，**不填挂载点**）。

2. **Swap交换分区**：16G（与内存大小一致，用于虚拟内存）。

3. **/ 根分区**：剩余全部空间，ext4格式，挂载点选 `/`。



⚠️ **关键保命设置（必看）：**

- 在分区列表中，找到老512G固态自带的 **EFI分区**（通常几百MB，fat32格式），选中它，点击“更改”，挂载点选 `/boot/efi`。

- 🚨 **绝对警告：千万不要勾选“格式化”！保持原样！一旦勾选Windows引导瞬间灰飞烟灭！**

- 界面底部的「安装引导器设备」下拉菜单，必须选择**装Windows的那块512G老固态**（通常是 `/dev/nvme0n1` 或 `/dev/sda`，不要选具体的分区号）。



## 步骤5：完成安装与重启优化

1. 填用户名密码，等待安装进度走完。提示拔U盘时拔掉，重启电脑。

2. 开机自动出现 GRUB 菜单，直接选 Windows 或 Ubuntu 进入。

3. **修复时间差8小时**：进入Ubuntu后，如果发现时间比Windows慢8小时，打开终端（Ctrl+Alt+T）输入以下命令并回车，重启即可解决：

&#x20;  ```bash

&#x20;  timedatectl set-local-rtc 1 --adjust-system-clock

&#x20;  ```

## 💡 补充小要点（日常维护与体验优化）



1. **共享盘开机自动挂载**：

&#x20;  Ubuntu默认不自动挂载NTFS。进入Ubuntu后，在应用列表搜索打开 **“磁盘” (Disks)** -> 选中那200G的NTFS分区 -> 点击下方的**齿轮图标** -> 编辑挂载选项 -> 关闭“用户会话默认值” -> 勾选“系统启动时挂载” -> 确定。以后开机就能直接读写。

2. **文件互传规范**：

&#x20;  以后互传文件统一放这200G共享NTFS分区，不用折腾去读取对方的C盘或根目录，避免权限问题。

3. **Windows大更新导致GRUB消失的急救**：

&#x20;  如果以后Windows进行大版本更新，强行重写了引导，导致开机直接进Windows（GRUB菜单没了）。**不用慌，系统没坏！** 重启狂按F2/F12进主板BIOS，在 Boot（启动）顺序里，把 `ubuntu` 移到第一顺位，保存重启即可恢复双系统菜单。

## 一、先回答休眠Swap的核心结论

1. **想要完整休眠（把内存全部存入硬盘、彻底断电开机恢复所有窗口）**

你的物理内存32G，Swap分区**必须≥32G**，只分16G、8G全都不能正常休眠，休眠会直接失败。

2. **只是睡眠（合盖待机，内存不断电）**

完全不占用Swap，Swap分8G/16G都无所谓。

3. **你不用休眠、仅日常开发、编译兜底防OOM崩溃**

32G大内存只需要**8G Swap**足够，16G属于浪费固态空间。



## 二、结合你的硬盘1T，两套分区方案二选一

### 方案A：你打算用休眠功能（32G Swap）

- NTFS共享：100G

- Swap：32G

- /根分区：剩余全部

适合：经常开一堆工程、IDE、浏览器，想关机后下次开机恢复全部页面。



### 方案B：不用休眠，只求省空间（更推荐开发）

- NTFS共享：100G

- Swap：8G

- /根分区：剩余八百多G

优势：根分区空间最大化，Docker、编译缓存、开发环境随便装，不会爆满。



## 三、补充你之前整套安装流程的两处风险提醒

1. 挂载旧硬盘EFI分区时，**绝对不要勾选格式化**，否则Windows引导直接损坏；

2. BIOS保持RAID On模式下，Ubuntu安装时大概率识别不到NVMe固态，优先提前无损切换AHCI。



## 四、补充灵活方案（不想多分Swap分区）

哪怕只分8G Swap分区，后续编译超大项目内存不够时，可临时创建swap文件扩容，用完删除，不用重新分区：

```bash

# 创建16G临时swap文件

sudo fallocate -l 16G /swapfile

sudo chmod 600 /swapfile

sudo mkswap /swapfile

sudo swapon /swapfile

```

不用了执行`sudo swapoff /swapfile && rm /swapfile`删掉即可。

# 二、RAID On 无损转 AHCI 的流程确认

你写的这套步骤**完全正确，操作顺序无问题**，可以直接照做，补充两处细节防踩坑：

1. `msconfig` → 引导，勾选**最小**（安全引导里的最小模式，不是别的子选项）；

2. BIOS修改SATA Operation为AHCI后，按F10保存重启，会自动进入Windows安全模式，等待系统自动加载AHCI磁盘驱动，不用手动装驱动；

## 补充利弊，你可以自行选择要不要转

### 转AHCI的好处

1. Ubuntu安装界面能直接识别你的1T佰维NVMe固态，不用额外加载RST驱动，安装流程更简单；

2. NVMe固态性能完整释放，跑分、读写速度无限制；

3. 固态监控工具、测速软件、Linux磁盘工具全部完美兼容。



### 不转（保持RAID On）的缺点

1. Ubuntu安装时大概率看不到新1T固态，需要额外内核参数才能识别，新手容易卡住；

2. 固态速度轻微受限，部分硬盘工具识别异常；

3. 重装纯净原版Windows时会找不到硬盘，需要注入RST驱动。



### 总结建议

既然你要装Ubuntu双系统，**强烈建议按这套无损流程切换AHCI**，一劳永逸避免各种硬盘识别、兼容问题。













# ⚠️ BitLocker弹窗完整处理方案

## 一、弹窗含义

你开启安全引导修改启动配置，系统检测到C盘开启了BitLocker全盘加密，**修改启动模式会触发BitLocker恢复锁**，下次开机强制要求输入48位恢复密钥才能进系统，输错无法解锁Windows。



## 二、操作分两种方案（优先方案1，无风险）

### 方案1（推荐，不用找密钥，零锁机风险）

先暂停BitLocker保护，再开启安全引导切换AHCI，步骤：

1. 打开「控制面板→BitLocker」，找到系统盘C盘，点击**暂停保护**

2. 确认暂停后，再回到系统配置勾选安全引导，弹窗点「是」继续

3. 完整走完AHCI无损切换流程，正常进Windows后

4. 再次进入BitLocker面板，点击**恢复保护**

> 优势：全程不会触发恢复锁，不需要翻找48位密钥，最稳妥。



### 方案2（不暂停BitLocker，直接点是）

1. 弹窗点确定继续，**必须提前找到并保存BitLocker 48位恢复密钥**（存在微软账户/打印的纸质文件/U盘）

2. 重启进BIOS改AHCI保存，开机后会进入蓝色BitLocker恢复界面

3. 输入完整48位密钥解锁，才能进入安全模式加载AHCI驱动

4. 完成全部切换步骤后系统自动解除锁定

> 风险：密钥丢失会直接导致Windows系统全盘加密锁死，文件无法读取。



---

## 三、关键补充提醒

1. **切换AHCI完成后，一定要取消安全引导**，否则每次开机都会进入安全模式；

2. 如果你找不到BitLocker恢复密钥，**绝对不要直接点确定**，必须先用方案1暂停保护；

3. BitLocker不影响Ubuntu双系统，仅Windows启动变更会触发校验，共享NTFS分区不受加密影响。



## 四、极简操作顺序（最优流程）

1. 控制面板打开BitLocker → C盘暂停保护

2. Win+R输入msconfig → 引导 → 勾选安全引导【最小】，弹窗确认

3. 重启按F2进BIOS，SATA Operation改为AHCI，F10保存

4. 自动进Windows安全模式，等待驱动加载完成

5. 再次打开msconfig，取消安全引导，重启正常进系统

6. 回到BitLocker面板，恢复磁盘保护
